# 芯鉴知微分阶段开发计划

## 工作原则

- 每次只实施一个 Phase，完成测试、构建和状态文档后停止。
- 修改前读取相关文件并检查 Git；不编造账号、设备、数据或密钥。
- 所有模拟数据明确标记为测试数据。
- 每个阶段以可重复命令和实际输出验收，失败必须调查原因。

## 阶段计划

当前进度：Phase 0、Phase 1 均已完成并通过实际运行验收；Phase 2 尚未开始。

| Phase | 目标 | 核心交付物 | 主要验收 |
| --- | --- | --- | --- |
| 0 | 项目调查与方案落地 | 上下文、架构、计划、状态与审计 | 明确现状、环境、风险；不写业务代码 |
| 1 | 项目骨架与运行环境 | Vue、FastAPI、Compose、健康检查、基础日志 | Compose 启动；前端调用 `/api/v1/health` |
| 2 | 数据模型与设备 API | SQLAlchemy、Alembic、设备认证、日志/读数/心跳 | 合法请求入库、非法令牌拒绝、pytest 通过 |
| 3 | 设备模拟器 | 正常、读取失败、离线、越界、数值不变场景 | 无真实 ESP32 也能稳定复现并入库 |
| 4 | 规则诊断 | `DiagnosisContext`、YAML 规则加载与匹配 | 三种核心异常确定性识别并有证据 |
| 5 | 故障树与分层提示 | 三棵故障树、原因评分、提示升级 | 原因有证据排序，能触发教师介入 |
| 6 | 学生端 | 状态、日志、趋势、诊断和反馈 | 真实 API、三类页面状态、构建与测试通过 |
| 7 | 教师端 | 班级看板、错误排行、学生详情和介入列表 | 真实 API、图表自适应、构建与测试通过 |
| 8 | RAG 知识库 | 案例模型、切分、导入、Embedding、pgvector 检索 | 带来源、相关性合理、幂等导入 |
| 9 | AI 结构化诊断 | 可替换 AIClient、Pydantic 校验、重试与降级 | 稳定 JSON；AI 不可用时系统仍工作 |
| 10 | 真实 ESP32 联调 | PlatformIO、DHT11、心跳/数据/错误上传 | 真实硬件闭环可演示且无密钥入库 |
| 11 | 测试与安全加固 | 单元、集成、E2E、安全与恢复说明 | 全套测试、构建、迁移和安全检查通过 |
| 12 | 部署与交付 | Dockerfile、Nginx、CI、部署/演示/排障文档 | 新电脑可按 README 启动完整系统 |

## 阶段门禁

每阶段开始前记录：当前发现、计划修改/新增文件、风险和验收命令。每阶段结束记录：修改/新增文件、迁移、执行命令、测试和构建结果、已知问题、待补充信息与下一阶段目标。

在用户明确输入“继续下一阶段”前，不进入后续 Phase。
