# 芯鉴知微故障树与分层提示设计（Phase 5）

## 阶段边界

Phase 5 只消费 Phase 4 已保存的结构化诊断与证据，不实现 Phase 6 学生端页面、RAG 或 AI 推理。计划指定的三棵树以课程示例模板保存：

- DHT11 读取失败：映射到通用 `SENSOR_READ_FAILED` 规则结果。
- LED 不亮：由可配置 `LED_NO_RESPONSE` 测试事件触发。
- 按键无反应：由可配置 `BUTTON_NO_RESPONSE` 测试事件触发。

三者均标记为 `status: placeholder`。这里的名称用于满足课程方案的示例范围，不表示开发板、传感器、引脚、接线或生产字段已经确定；实际课程确认后应审核并替换 YAML，而不是在 Python 中增加硬件特例。

## 评分约束

故障树定义触发证据、候选原因、原因证据权重和四级提示文本。匹配器只提供通用事实解析器和比较运算符：

- `diagnosis_error_count`：统计 Phase 4 结构化错误类型。
- `log_event_count`：统计由配置指定的事件码。
- 运算符：`eq/gte/gt/lte/lt`。

每个候选原因由命中证据权重求和，最高 100 分，并按分数降序、原因 ID 升序输出。低于 40 为低置信度，40–69 为中等，70 以上为高置信度。根异常证据权重仅为 20，因此没有原因专属证据时不能生成高置信原因；没有任何证据的原因不会输出。

## 提示升级与历史

默认示例阈值同样保存在 YAML：首次为 Level 1，连续 3/6/10 次或持续 300/900/1800 秒分别升级至 Level 2/3/4。任一条件达到即可升级，Level 4 设置 `teacher_intervention_required=true`。

历史记录保存故障树版本与哈希、首次发现时间、失败次数、持续时间、排序原因和当级提示。同一诊断和同一树唯一，重复 API 调用不会人为升级；超出树配置的连续窗口后重新从 Level 1 计数。

## 临时审阅边界

`REVIEW_ACCESS_TOKEN` 环境变量保护，供知识/运维工作区内部调用；教师前端不再依赖
该令牌。仓库不提供真实令牌。
