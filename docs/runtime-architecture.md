# 芯鉴知微运行架构（Phase 9.5）

## 1. 一句话说明

传感器通过杜邦线连接 ESP32；ESP32 通过 USB 连接学生电脑完成供电、烧录和串口调试，同时通过实验室 Wi-Fi 使用 HTTP + JSON 向芯鉴知微后端上传数据。学生端和教师端只访问 FastAPI 后端，只有后端在策略允许时才可调用 DeepSeek。

Phase 9.5 只确定运行边界，不代表 ESP32、传感器、GPIO 或课程参数已经选定。真实硬件型号和接线必须在 Phase 10 前由项目方提供并审核。

## 2. 物理连接与服务拓扑

```text
DHT11、LED、按键等实验器件
        │
        │ 杜邦线（具体 GPIO、供电和上下拉待确认）
        ▼
ESP32 开发板
        │
        ├── USB ──> 学生电脑
        │           · 供电
        │           · 烧录固件
        │           · 查看串口日志
        │           · 开发调试
        │
        └── Wi-Fi + HTTP + JSON
                    │
                    ▼
        实验室局域网中的芯鉴知微服务器
        ├── Nginx / Vue 学生端 / Vue 教师端
        ├── FastAPI 后端
        │   ├── 设备鉴权与字段校验
        │   ├── 规则引擎与故障树
        │   ├── Diagnosis Episode
        │   ├── 本地 RAG
        │   └── 可选 AI 解释
        └── PostgreSQL + pgvector
                    │
                    │ 仅 AI 增强时需要公网
                    ▼
             DeepSeek 官方 API
```

边界是强制的：

- ESP32 不直接连接 PostgreSQL，也不直接调用 DeepSeek。
- 学生端和教师端不直接调用 DeepSeek。
- 浏览器和设备只调用 FastAPI。
- PostgreSQL、pgvector、规则、故障树、RAG、缓存和 AI Provider 都由后端统一编排。
- DeepSeek 只能解释已经形成的确定性诊断，不能覆盖错误码、证据和故障树排序。

## 3. 三类设备数据

### 心跳

`POST /api/v1/device/heartbeat`

心跳用于更新最后在线时间、判断在线状态和识别离线。请求必须携带设备 ID 与设备令牌，令牌只在后端校验，不写入业务载荷。

### 传感器读数

`POST /api/v1/device/readings`

读数使用通用 `sensor_type + metric_key + value + unit + observed_at` 模型，供趋势图和确定性范围判断使用。温度、湿度、光照、距离等只是可配置指标，不在核心代码中固定具体型号或阈值。

### 日志和错误码

`POST /api/v1/device/logs`

日志用于保存设备运行过程、触发规则、聚合 Episode 并形成故障树证据。错误码是确定性判断输入，不由 DeepSeek 生成。

完整链路：

```text
ESP32 采集数据
  → 生成统一 JSON
  → Wi-Fi 发送 HTTP 请求
  → FastAPI 校验设备令牌、字段和时间戳
  → PostgreSQL 保存
  → DiagnosisContext
  → YAML 规则
  → 故障树原因排序
  → 检索 approved 知识
  → 确定性说明模板
  → 策略允许时查询缓存并可选调用 DeepSeek
  → 学生端与教师端展示
```

## 4. 学生和教师如何使用

学生在浏览器进入 `/student`，使用当前临时设备凭据登录，查看设备状态、趋势、证据、可能原因、排查步骤、Hint Level 和诊断限制。USB 串口用于开发调试，不是网页数据传输通道。

教师在浏览器进入 `/teacher`，通过临时审阅凭据查看设备状态、异常排行、趋势、日志和介入队列。正式学生、教师、班级和角色账号仍未建立，当前界面不能把设备等同于真实学生身份。

## 5. 局域网与公网

### 没有局域网

设备无法上传，学生和教师也无法访问服务器，核心链路不可用。这是系统不可用状态。

### 有局域网但没有公网

以下能力正常运行：

- 心跳、日志和读数上传；
- PostgreSQL 持久化；
- 规则、故障树和 Episode；
- 本地全文检索、已存在的本地向量检索和 RRF；
- 确定性模板、学生端、教师端、教师介入判断；
- 已验证的 PostgreSQL AI 解释缓存。

DeepSeek 新调用不可用。后端保存明确审计结果并返回确定性诊断，不返回 HTTP 500 或空白卡片。

### 有公网但没有 API Key

`AI_ENABLED=false` 或 `AI_API_KEY` 为空时，AI 状态为 `disabled`，后端不发起请求。健康检查、设备上传、诊断和前端保持正常。

### DeepSeek 异常

超时、限流、余额不足、鉴权失败、网络错误、非法 JSON 或 Pydantic 校验失败都会进入确定性降级。审计只保存安全错误分类和请求摘要，不保存密钥或完整敏感上下文。

## 6. DeepSeek 生产决策

- Provider：DeepSeek 官方 API。
- 模型：`deepseek-v4-flash`。
- 模式：非思考模式，发送 `thinking.type=disabled`。
- 传输：复用统一 OpenAI-compatible `AIClient`。
- 路由：`cache → deepseek → deterministic_fallback`。
- 默认状态：`AI_ENABLED=false`，仓库不保存真实 API Key。
- Embedding：优先本地生成，不因对话模型选择 DeepSeek 而改用收费云端 Embedding。

真实调用之前仍必须依次通过策略、Episode/设备次数、Token、单次预算、每日预算、知识审核、隐私白名单和 Pydantic 校验。

## 7. DeepSeek 数据最小化

后端 `phase9.5-allowlist-v1` 准备层只允许发送：

- Episode ID、Diagnosis ID、匿名设备短标识；
- 实验模板标识和聚合设备状态；
- 错误码、命中规则、规则证据；
- 最近 3–10 条与故障直接相关的关键日志；
- 聚合后的传感器最小值、最大值、最新值和样本数；
- 故障树原因、Hint Level、介入建议和限制；
- 已正式批准或显式测试允许的知识块及必要来源信息；
- 学生主动提交且已脱敏的技术问题。

明确禁止发送学生姓名、学号、班级实名、手机号、身份证号、邮箱、账号密码、设备令牌、Authorization、API Key、数据库密码/连接串、Wi-Fi 密码、教师私人备注、完整原始请求、无关历史日志和服务器环境变量。

## 8. 知识来源与责任链

正式知识按以下顺序选用：

1. 官方硬件资料；
2. 学校和课程正式资料；
3. 教师或硬件负责人确认的参数；
4. 可复现、可追溯并有修复结果的真实案例；
5. 教材、论文和可靠技术文档等补充资料。

审核人不能替代来源。资料整理人登记来源、URI、版本、定位和适用硬件；技术初审人核对接线、电压、GPIO、采样限制和修复安全；正式审核人决定是否进入正式 RAG及撤回或替代。三者必须职责分离，测试身份必须明确标记，不能冒充真实教师。

知识状态为：

```text
draft → pending → technical_reviewed → approved
```

另有 `rejected`、`withdrawn` 和 `superseded`。正式 RAG只检索 `approved` 且非测试、未撤回、未替代的知识。AI 生成内容只能从草稿开始，不能自动批准。

## 9. 三种部署模式

- 开发模式：开发者 Mac/Windows + Docker Desktop + Docker Compose，用于测试、模拟器和联调。
- 课堂试运行：实验室固定电脑、小型主机或学院服务器运行 Docker Compose；设备、学生电脑、教师电脑和服务器处于同一局域网。这是第一版课堂与答辩推荐方式，不要求公网 IP、域名或云服务器。
- 正式部署：可使用校园网服务器、学校私有云、学院服务器或国内云服务器；必须另外完成 HTTPS、域名、防火墙、账号权限、备份恢复、监控告警、数据保留、隐私合规、限流和多班级隔离。

更详细的运维边界见 [部署说明](deployment.md)。
