## 2. R01：自由理由与教学范围

### 触发、预期与根因

触发：输入只有一次电压读数、没有规范范围；允许动作只有配置核对，模型却输出规范性判断和其他检查需求。预期：当前交付只能陈述有来源的事实和本次适用的核验项。

`ai/schemas.py` 用字符串承载 reason/missing_evidence；`knowledge/validation.py` 验 ID 归属、候选关系与动作集合；`ai/output_contract.py` 保留 reason，并将自由缺口加上 unverified 后继续投影。**引用存在不等于引用支持某句话，未核验标签也不能证明教学适用。** 当前没有完整课程器材合同，不能把所有仪器建议一概判为违反已确定课程要求。

### 决策：先收紧交付，按需要扩展表达

最小修复由 `ai/output_contract.py` 承担共同投影职责，准入数据由现有知识/包与来源校验提供：

1. 当前用户输出和下阶段输入采用服务端受控说明、引用记录及局限；模型自由 reason 只保留在受权限控制的原始审计中，不作为事实依据或再次外发。不得把未经许可的自由证据文本直接套模板变成“事实已确认”。
2. 核验需求来自当前包/故障树中经过范围和版本验证的指导项。**动作不自动等同观察需求**：仅对明确适用的项目建立显式映射；不能机械把全部 allowed actions 复制成“缺少证据”。无适用项时给固定教师求助/材料不足说明，不自动补器材与操作。
3. 明确保留能力变化：最小方案会缩小自由解释与任意追问的表达范围；用合法正例证明仍能给出有用指导，不能以“全部清空”作为修复完成。
4. 扩展时登记版本化 `observation_request`：稳定 ID、实验/组件/阶段、目标材料、前提与器材、来源、课程审核状态。模型只选允许 ID，服务器生成文字。许可目录缺失标待定，不由开发者猜课程要求。
5. 更细的事实说明使用可溯源 `observation_id/claim_id` 与有限谓词。数值范围、比较和支持方向来自审核规范与类型化记录，不能让模型或正则将任意文本转换成已验证事实。根因确认继续由已有独立来源决定。

不用关键词黑名单代替语义；不增加一个模型裁判来充当确定性许可。

### 相邻入口、兼容与撤回

共享投影须覆盖：新响应校验 → 唯一键竞争/缓存重放 → 图状态/Checkpoint 恢复 → 二阶段输入 → 教师中断快照/最终结果 → `current_advice` 当前读取 → 学生/教师 API 与页面。特别处理前端旧 `missing_evidence` 回退，不能后端限制后由旧字段重新显示。教师真实编辑与模型原文分开，不伪造审核。

区分 Provider 合同版本、交付投影版本和资料许可版本；缓存身份绑定实际 prompt/schema/hash。历史原始响应不改写、不自动收费重生成；缺新结构的历史记录用可验证材料和固定说明只读降级。默认不需数据迁移，确需新增持久字段再设计追加迁移。撤回本轮差异时仍保留安全投影或关闭相应增强，不恢复自由建议旁路。

## 3. R02：保留配置事实，独立评估候选

### 已知原因与待验证假设

提示 v2.12 已写明 ranked 不等于根因确认，但另有笼统“资料不足必须 unknown”；输出缺独立配置事实字段，unknown 摘要统一为无法排序。这些是可核查的工程原因。案例限制压过正向证据、单候选措辞歧义、合成来源文案和随机性是待验证假设，不能称模型内部真实思维。

### 决策与最小改动

先冻结三个不同判据：**配置是否符合要求、证据是否支持某候选、物理根因是否确认**。单候选可以有证据支持；不能规定“有配置差异就必须 ranked/medium”，也不能要求根因已知才允许报告配置差异。

优先检查现有生产输入能否提供类型化实际配置及适用规范。若能，复用现有来源与包身份，生成只读 `configuration_observation`：对象、实读值、要求值、证据 ID、时点/版本、`match/mismatch/unknown/conflict`。映射到候选须有版本化规则；差异本身不自动提高支持等级。如果目前只有自由文本，先补合法生产方和 Schema；没有该前提时只能展示来源报告，不能宣称自动比对已落地。

服务器独立保留“当前配置差异”，模型仍可对物理因果 unknown；无需一次重写整个图或让模型再输出根因确认状态。R01 投影必须允许这些经过验证的事实通过，不能只靠固定未知摘要抹掉信息。

候选利用的提示试验单独进行：将资料不足限定到“是否足以评估候选支持”，保留全部证据/冲突限制，加入对称通用例子。CoT 顺序、模型设置、上下文与图保持一致，实际提示升版本；不把 K02/K04 的具体答案写入提示。新保留集没有稳定改善或增加无据支持时，不采用新提示。提示效果不能代替本地事实合同。

兼容采用可选、版本化的服务器观察投影，老记录缺字段时不猜测；预检、类型、缓存/Checkpoint、当前读取与页面同步。撤回新提示不撤掉已经独立验证的来源事实，旧客户端无法安全消费时降级到已有确定性输出。

## 4. R03：预算与实际阶段准入

### 已确认链路

默认 4000 是应用准入阈值。当前估算器按完整 system+user UTF-8 字节数除 3 向上取整；解释打包超量时逐个移除完整可选案例，必要材料仍超量或必需知识被全部省略就降级。该保护本身正确。

| 历史合成请求 | 应用估算 | Provider 返回 input_tokens |
| --- | ---: | ---: |
| DHT11 推理 / 解释 | 3441 / 4746 | 2934 / 3909 |
| LED 推理 / 解释 | 3117 / 4401 | 2466 / 3495 |

四条数据不证明估算总是偏高。4000 容量检查中 DHT 必要材料仍为 4126；LED 删案例后为 3682，却失去必需知识。LED 的重复 sensor_values 单独移除仅减 126；没有证据支持“删一个字段即可修好”。日志/知识的不同表示保留了不同 ID、内容或来源，不可凭文字相似删除。

通用 workflow fixture 使用 32000/不强制知识，不能代表实际配置。相邻缺口：离线 preview 对两阶段统一按必需知识判断，实际推理与解释准入不同；当前结论为静态代码不一致，本轮未作新的端到端复现。

### 决策与实施位置

1. 先增加实际配置快照的双阶段容量检查，记录配置来源、总输入、单案例长度、输出与时间限制、知识要求。预检只接收白名单配置，不读取密钥；场景不能暗中覆盖被称为“实际配置”的参数。
2. 提取共同的分阶段准入政策供 `context_builder`、governor、preview 和解释/推理服务使用；区分材料完整、可选来源选择、预算适配与本阶段是否允许调用。保留无合格知识、合格知识被预算省略、必要材料超量三类原因及授权/来源失败优先级。
3. 增加专门 Provider 输入投影前，列逐字段保留/合并及来源映射。先从完整原始材料收集敏感值，再清洗/投影；保留证据身份、条数、否定、条件、规则、动作和来源版本。manifest/hash 绑定实际发送内容。只减 Token 却丢上述信息的方案拒绝。
4. 保留现有保守估算，显式比较默认 4000 与有界 10000 候选 profile；后者已有两包历史依据，仍须用改后合同复验。禁止自动无限扩容；费用、单次/整段时间、次数和并发限额继续有效。**本轮不修改业务配置。**
5. 若确需分阶段上限，用一个 StageBudget 解析器并定义旧变量别名、优先级和冲突处理。估算校准另开单变量验证，涵盖模型版本与中文/英文/JSON 边界，不能从四例推出通用缩放系数。

先保持数据与审计结构，必要时只升级输入投影/缓存身份；回退投影和 profile 成套执行，历史费用及响应不回填。新合同可能变长，最终容量验收放在 R01/R02 合同稳定之后。

## 5. R04：隔离 Loop 的任务合同

本轮内存反例确认：已有 LED 观察仍接受 ask、sensor 接受 observe_led、只有症状允许空引用 finish；不同工具返回新 ID 的相同内容仍算机械进展。原型未被产品导入，不将其写成线上漏洞。

### 决策：共享任务合同约束动作

建立独立版本原型，保持历史源码和响应不变。一个纯函数任务合同供执行器、模型输入、规则基线和评测投影共同使用：

| 合同 | 必需内容 |
| --- | --- |
| 任务与需求 | 服务端实验/组件/任务/包身份，requirement_id、材料类型、允许工具/问题、满足条件与停止目标 |
| 来源 | 记录 ID、学生报告/设备命令/配置读取等类型、会话/时点/版本、有效性；报告不升级为独立物理确认 |
| 材料状态 | not_checked、present、checked_empty、conflicting、stale |
| 问题状态 | unasked、pending、answered、cancelled；后两者与人工答复恢复为拟新增能力 |

- query 只访问当前未满足需求对应的授权只读工具，查询后重验范围/版本，按需求满足或冲突澄清计算进展；同文独立观察不能误去重。
- ask 仅在当前适用、未回答/挂起、相关存档已查空或存在明确需核对冲突时允许。过期材料可按明确依据重新核验，不能永久禁止同类问题。
- finish 由服务器判定，区分 `finish_satisfied` 与有依据的 `finish_unknown`；后者说明缺口及无法/无需继续的原因。预算耗尽、工具失败单独记录，不能伪装完成；两种 finish 都不确认根因。
- 原型选择**不合规动作立即结束该模型回合，交规则策略**，不增加纠正重试。拒绝时零提问/工具副作用，步数和审计保留。
- 模型只在多个 eligible_actions 间选择；只有一个时走确定性策略。规则与模型使用同一结构状态与动作集合，不再由规则独享夹具辅助标志。

旧快照缺任务合同只能只读。第一阶段无产品 DB/API 改动，停止新原型即能撤回。接入产品需要另行实现：稳定请求/问题/答复身份、持久状态、答复幂等、授权在等待与写入/交付前复核、调用结果未知不盲重试、来源与会话隔离。现有学生反馈枚举不能直接承载任意追问答复；历史 JSON 恢复试验不能当作这些能力已具备。

| R04-A 业务资格 | Q01/Q02 重问、Q05 跨实验、Q03/Q06 未查先问、空引用提前完成 | 查空后可问，已满足可结束，冲突可重核；拒绝零问题/工具副作用 |
| R04-B 时序 | 等待/查询返回后撤权、换包、旧快照恢复 | 有效权限正常继续；接入阶段再验问题/答复原子性及同 request 一次生效 |

未来效果实验先冻结：模型版本/设置、两臂提示与输入 hash、样本与重复数、允许输出判据、预算及停止条件。本设计建议每个新语义场景每臂至少 3 次重复以暴露波动，不能将小样本视为统计证明；样本总量和费用先按最终 payload 核算再执行。每条判据独立记符合/不符合，未审阅记 null/not_run，不把失败抵消为总分。候选方向是否合理及课程范围需独立教学审阅，尚无教师真值的部分明确保留。

实施顺序：

1. 冻结事实/需求语义与验收材料，盘点真实生产字段；先固化 R01 和预算预检不一致反例。
2. R01 共用投影与相邻入口闭环，同时为 R02 保留合法配置事实；先有限合同，不自动扩成任意语义推理系统。
3. R02 类型化观察按生产字段可用性推进，提示效果作为独立可撤回试验。
4. R03 在新合同稳定后做输入投影、容量与配置比较，避免多变量同时改变后无法归因。
5. R04 在独立原型补合同和过程验收；通过后才评估模型是否比同等信息的规则策略有实际收益。
6. 先跑受影响单元/集成反例，跨流程实施完成后执行一次必要完整门禁；真实模型、数据库迁移、部署、硬件与课堂分别报告，不借历史通过数证明新代码。

### 既有设计不可遗漏

| 既有设计 | 本轮方案的约束及实施后证据 |
| --- | --- |
| CoT 五步 | 保留当前请求内核对与审计，记录真实 prompt/version；单变量比较不删除实质规则，不要求内部思维链 |
| LangGraph | 固定图职责、教师中断、终态、Checkpoint/幂等与恢复继续回归；查询原型不替换主流程 |
| 已采纳的 RAG/上下文设计 | 完整材料单元、案例适用性先于选择、两阶段来源 manifest、预算省略与实际发送对应；不冒称已上线向量检索 |
| 三类记忆/来源 | 事实、经验、工作记忆的不同可信度；源停用、包快照、当前建议和历史审计分别检查 |

| 其他共享调用方 | 输入/治理改动反查案例润色等调用方；保持受控完整表述和审核资格，不重新开放自由改写 |

## 7. 完成判据与仍需确认的边界
