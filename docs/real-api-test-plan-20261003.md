# Kimi 真实 API 接入全面测试方案

设计日期：2026-10-03。状态：**方案设计，尚未实施或执行**。适用对象：芯鉴知微当前固定诊断流程及 Kimi `kimi-k2.6` 接入。本文扩充此前的首轮方案；既有修复记录是回归材料，不是本方案的执行结果。

目标是回答：真实模型接入后，学生和教师能否得到有依据、权限正确、状态一致的结果；模型不可用时能否继续完成教学操作；增加 AI 是否带来了可观察的帮助。本轮只交付方案，不改代码、配置、数据库，不创建测试环境、不发起模型调用、不部署。

## 1 当前依据和验收范围

截至本次只读核对：主链是规则识别异常、故障树限定候选、AI排序与解释、教师审核；还有案例润色入口。没有通用聊天或模型自主工具执行。推理Prompt已为 `evidence-reasoning-v2.10`，已有冲突输入与必填 `error_type` 修复。详见[AI设计](ai-diagnosis-design.md)、[接入说明](kimi-api-integration.md)和[首轮修复报告](../output/audits/kimi-round1-fix-20261003/report.md)。

既有真实调用使用合成材料、主要直接调用客户端和验证器；尚不能据此验收完整的持久调用治理、授权变化、断点恢复和最终页面。LED无关建议及泛化 `text_only` 限制仍是语义回归重点。DHT11/LED资料包处于测试草稿，实物真值和课程判据另行确认。

| 结论层级 | 本方案如何取证 | 不可替代的材料 |
| --- | --- | --- |
| 软件行为 | API、数据库、调用审计、Checkpoint、浏览器的合成流程 | 原始Kimi回答不能证明数据库及页面正确 |
| 真实模型行为 | 固定版本、冻结输入、实际发送及响应、逐项校验 | Mock结果不能证明Kimi会如何回答 |
| 语义与建议适用性 | 独立预期、完整输出、领域人员逐条审阅 | 开发代理观察和关键词检查不替代人工验收 |
| 实物与课堂 | 后续独立硬件证据和教师/学生试用记录 | 本轮合成资料不证明接线安全、根因真值或教学效果 |

若历史状态文档与近期记录冲突，以日期、源码、具体执行证据分别判断；例如历史“Provider未就绪”文字不能覆盖近期真实连通记录，也不能由连通记录推断运行服务已启用。

## 3 环境和版本设计

未来执行时分三条通道，结果不互相替代：

1. **本地确定性通道**：隔离PostgreSQL、实际应用服务和可控Provider替身。负责坏输出、并发、超时、断流、崩溃、预算与权限时序，可精确重复，不消耗真实API费用。
2. **真实Provider通道**：相同业务配置及调用治理，只把模型端换成Kimi官方服务；少量必要场景穿过浏览器、FastAPI、固定LangGraph、数据库到最终页面。直接客户端探针仅用于分层定位，不能替代此通道。
3. **语义审阅通道**：将独立预期与实际最终交付内容交给审阅者；只读脱敏材料，无权调用模型或修改结果。

隔离环境绑定回环地址或明确的测试网段；启动前核对DSN、容器、Checkpoint存储和测试身份，禁止回退业务数据库。合成身份至少包括同班两位学生、跨班学生、任课教师、无该班权限教师和管理员；设备凭据与用户登录凭据分开。测试用“已审核测试包”与正式发布包分开，不改变现有资料包状态。

冻结清单包括提交号及未提交源码哈希、依赖锁、迁移Head、Prompt/Schema/输出合同/图版本、模型ID、请求参数、资料包版本与哈希、已清洗输入指纹、测试集版本及期望版本。开发集调参后冻结最终候选；保留集验收期间不改Prompt、预算或判据。改变后生成新运行编号。

本方案执行基线拟沿用输入4000 tokens、输出1000 tokens、每次调用总期限30秒、响应字节上限1 MiB；这些是当前软件默认边界，执行前读取实际有效值并冻结。不能把“两阶段各30秒”写成“整个工作流30秒”。本机配置、Compose映射和真实发送参数分别核对。

## 4 以八条真实使用流程组织验收

这些流程将第5节的检查串起来，不再另加为独立缺陷数。正常与异常分支均要保留操作时间线。

| 流程 | 贴近使用的步骤 | 关键观测和通过条件 |
| --- | --- | --- |
| J01 学生首次排查 | 登录→进入固定实验会话→上传合成读取失败→查看诊断→请求AI辅助→刷新 | 异常/候选/证据来自本次任务；推理与解释分别有调用记录；刷新不再付费；未知仍显示未知 |
| J02 多种原因同一表现 | 同一症状对应接线与时序候选→查看依据→提交“仍未解决”→重新检查 | 无区分证据不强排；反馈不确认根因；检查只分析已上传数据，不声称重新采样 |
| J03 断网和反复点击 | 发起请求→断开浏览器连接→重复点击/关闭标签→重新登录恢复 | 同一操作身份可追溯，已成功阶段不重发；结果未知不自动退款重调；最后页面与保存状态一致 |
| J04 授权途中变化 | 请求等待Kimi时教师撤销学生权限或解除设备占用→响应返回→旧页刷新 | 撤权后不得交付受限结果/写入；授权错误按权限处理，不能伪装成普通AI降级绕过权限 |
| J05 知识途中失效 | 推理使用测试资料→解释前停用来源或改变适用版本→查看旧页/仪表盘 | 停用材料不继续作为当前建议；历史审计保留；不同入口都重验来源与冻结调用身份 |
| J06 教师审核与润色 | 分支A：学生求助→教师处置；工作流确实进入待审时，分别测试approve/edit/reject。分支B：学生resolved且符合草稿条件→生成案例草稿→AI润色→案例审批 | 两类审核状态分开验收，不把求助直接当草稿来源；润色保留事实/来源，旧稿不覆盖新版本，resolved不确认根因，合成材料不发布为正式知识 |
| J07 一堂课的集中操作 | 合成班级集中进入、上传、查看、少量请求AI→某些请求遇429/慢响应 | 非AI流程持续可用，等待有期限，限流有明确状态，预算不超分配；详见第8节负载分层 |
| J08 来源混淆与旧页面 | DHT11与LED任务分别存在→切换任务/账号→打开旧结果→旧证据后补新证据 | 不串案例、组件、账号和版本；旧建议不能覆盖新结论；电平命令、实测电平、物理发光不混同 |

每条流程至少核对四份证据：用户实际操作及页面、API响应、业务/Checkpoint状态、物理Provider请求与额度记录。合成事件时间与服务器接收时间分别保存。

## 5 六十个基础检查场景

下列为**60个场景定义**，不是60次付费调用或60个独立根因。D表示本地确定性测试，R表示真实Kimi抽样，U表示浏览器，H表示领域人工语义审阅。同一场景可采用多种方法，分别记录。已有测试可复用，但只有本轮实际执行才计本轮覆盖。

### 5.1 接口契约 PC01 至 PC06

| --- | --- | --- |

## 6 数据集和预期设计

采用三份独立材料，不能让模型看到评测答案：

- **开发回归集**：已有冲突漏传、error_type遗漏、LED污染、泛化限制、已知注入和历史状态缺陷。用于验证修复，不计为未见泛化证据。
- **冻结保留集**：新构造24个合成案例，按诊断8、解释6、润色4、安全变体6分层；不得仅更换已有样例UUID。至少一半使用已填充分支完整的实验上下文，其余有明确缺失/冲突，避免全是资料不足。应由不同于修复者的评测审阅者先审核预期；无人可独立审阅时明确降低结论范围。
- **完整流程事件集**：J01—J08的事件顺序、身份、包/来源版本、授权变更和预期落库副作用。模型只接收运行时本应可见的材料，不获得未来事件或隐藏故障标签。

充分证据场景的期望来自人工编写的合成规则事实和对应约束；若要判真实硬件根因，必须另外取得独立测量。不能把故意断线的隐藏标签直接给模型，也不能因合成数据作者知道故障就要求模型在不可区分证据下猜中。

分组隔离按实验问题过程、模板家族、会话/设备/时间组织；同源改写或同一事件的兄弟样例不得分跨开发与保留集。每条场景记录稳定ID、来源/测试性质、适用条件、入口、事件时间线、必要数据、独立预期、允许动作、禁止副作用、预期阶段请求上限、所需审阅材料和关联规则。对照至少包括：有/无冲突、证据充分/不足、来源有效/失效、权限允许/拒绝、器件有关/无关、正常/错误响应。

同一实验增加无关日志、交换叙述顺序时，事实与授权预期不应改变；增加相反证据、删除关键观察、撤权时预期应相应改变。变化关系由独立规则预先定义，不能要求自然语言逐字相同。

为观察随机性，预先从24例选6个高风险样本各追加2次：共36次计划物理调用。变化顺序随机化并记录，输入和版本固定；重复不是新独立样本。某次失败不能因后两次成功而删除。若根据保留集结果改Prompt，该集转为开发材料，后续泛化验收需新保留集。

## 7 判定方法和退出条件

### 7.1 分开判断系统防护与模型质量

一个不合规模型响应被正确拦截，可以记“系统防护符合”，同时记“模型该项不符合/增强未交付”。不能将所有回退都算模型成功，也不能把正确unknown记作诊断失败。正向DG03防止“全部拒绝/全部unknown”的系统取得虚假好结果。

语义条目优先复用 `backend/evaluation/semantic_rubrics.json` 的稳定ID，并补O01建议相关性要求，定义与场景双向映射，不复制第二套相冲突标准。每条断言/语义条目只判符合或不符合；未执行、受阻、不适用、缺材料记录执行状态及原因，`judgement=null`。不设加权总分，不用大量低风险通过抵消一项关键安全不符合。规则来源为[开发准则](development-guidelines.md#ai-quality)，报告格式遵循[测试报告约定](test-reporting.md)。

语义审阅只写单一要求及材料：结论是否越过证据；建议是否属于本次对象；引用是否真正支持原因；限制是否有输入依据；是否把建议说成已执行；语言是否使学生误认根因已确认。每条分别记录，正式领域审阅由教师/硬件负责人完成，争议保留原意见并由另一位审阅者复核。开发代理可发现线索，但不冒充教师签署，也不用Kimi评判Kimi。

### 7.2 记录的事实指标

| 观测 | 口径 |
| --- | --- |
| 需求覆盖 | 已触发并取得证据的场景ID/适用场景ID，未触发不算覆盖 |
| 模型结构与业务结果 | JSON解析、Schema、业务接受各自的分子/分母；不混成“准确率” |
| 最终交付 | 模型原文、验证后结果、保存内容、最终DOM之间差异及来源；同一缺陷关联所有受影响入口 |
| 调用与费用 | 逻辑操作、阶段、物理尝试、缓存命中、usage、预留、估算、待核对账单分别统计 |
| 可靠性与延迟 | 等待准入、构造上下文、HTTP请求、验证/落库、页面交付分段；另计非AI业务耗时 |
| 语义与效用 | 每条符合/不符合及证据、正确保留未知、无效建议、对学生完成任务的实际影响 |

耗时必须带样本数、环境和失败样本；小样本先报各值/中位数/最大值，不拿少数请求的p95声称服务SLA。重复调用有相关性，不由几十条合成样本估算“生产故障率”。

### 7.3 阶段门槛

- **准入**：环境/版本/输入/预期/预算/出口已冻结，独立环境可确认，离线契约反例通过。任一不满足，真实API阶段不开始。
- **软件防护验收**：适用的必需精确断言全部符合；越权、泄露、错写、重复副作用、无界调用等未关闭缺陷阻止相关范围通过。保留失败原件。
- **真实增强候选验收**：软件防护通过，正向增强场景确实调用且产出被允许的帮助；结构拒绝、超时、限流等逐项处理，不用回退掩盖效果缺口。
- **语义验收**：必需语义材料齐全，逐条独立审阅完成；任何必要不符合未关闭时，不宣布整体语义通过。条件缺失可在其范围外单独给软件结论。
- **试点/上线判断**：本方案结果不自动授权部署；教师判据、实物证据和目标环境验收另列。不得把“可继续内部测试”写成“可以正式上课”。

## 8 故障时序和课堂负载

调用时序固定观测点：准入前→预留后发送前→已发送未收到→收到未落库→持久化后未回执→交付前→用户再次读取。撤权、来源停用、进程中断分别在明确观测点注入，采用可控屏障确认触发，不能只sleep几秒后假定碰到了竞争窗口。

发送结果未知保持独立状态，后续恢复先查持久记录；不自动假定服务商未处理。符合条件的有限重试与“未知发送不重试”分别测试。RFC重试原则用于检查，不代表任何POST都可安全重发。

**课堂人数、实际使用频次和可接受等待时间尚未确认，不预填容量或SLO验收值。** 可先在本地Provider替身下进行1→5→10个并发业务会话的探索，每档5分钟；这只是探索负载，不代表课堂规模。扩大负载前依据观测确定下一档、资源预算和中止条件。测CPU/内存/连接池/排队/锁等待及恢复，不能将本地容量等同真实Kimi吞吐。

真实Kimi阶段初始最多1个在途请求，发送间隔依据当时账户RPM/TPM/并发余量设置；同时浏览/反馈不等于同时外发模型。遇429停止当前真实批次，保留头部允许字段，核实限制后再设计下一批，不主动制造服务商高压。响应头名称及可用性按聊天接口实际观察，不借用其他接口的限速头假定。

探索阶段记录各并发档位非AI关键操作的基线及退化情况，不作课堂容量合格判定。已配置的物理调用总期限必须遵守并释放资源；队列最长等待和完整工作流期限需要结合实际阶段数、课堂需求及本地处理预算确定。缺队列期限、课堂目标或观测点时，记为尚无相应验收依据，不能临时猜一个SLO或放宽断言当通过。

## 10 取证和缺陷闭环

拟为每次运行生成独立目录，保留：方案/源码/依赖身份、输入与预期版本、适用性清单、脱敏实际请求及原始响应、阶段记录、断言结果、必要数据库/Checkpoint快照、浏览器trace/截图、费用账本和人工审阅表。保存请求ID与允许的状态头，不保存Authorization、Cookie、真实密钥或无关个人资料。

只允许合成业务材料经权限检查、白名单投影及清洗后外发。合成秘密是验证清洗的哨兵，预期不得进入真实Provider请求、公开日志或审计正文；先在本地替身通道验证，发现泄漏则停止真实发送。本地受控夹具保留哨兵及独立预期，模型不接收答案文件或未来事件。后续若需要真实课堂材料，先形成独立的数据范围和外发安排，不能把本方案当成真实学生数据外发授权。

每项发现记录：触发入口与条件→独立预期→实际材料→模型/应用/配置/环境/测试缺陷归因→受影响相邻入口→根因状态→修复及回归证据。相同根因在多个页面触发归并，但保留各入口证据；重试通过不能覆盖原失败。

修复后只复验原反例、正常近邻及实际受影响模块；跨完整链路的变更执行所需完整门禁。调参样本不再充当独立保留集。连续语义漂移或安全不符合时，冻结失败版本并停止扩大真实批次。
