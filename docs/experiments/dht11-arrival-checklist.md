## A. 上电前：身份、接线与构建（T0 → T1）

- [ ] 对照板卡及器件实物标识和随货资料，确认与首轮选型、Aosong V1.3说明书适用；不符则记录差异，先暂停烧录/接线推断。
- [ ] 确认持久PlatformIO Core环境可运行且版本/锁定依赖可取得；本轮`/private/tmp`审计环境不能作为长期安装凭据。
- [ ] 断电后按[指南2.2节](dht11-internal-lab.md#22-断电接线)逐脚核对：DHT11脚1→3V3、脚2→GPIO4且经4.7kΩ到3V3、脚3 NC、脚4→GND；拍照并检查电源轨/公共地。
- [ ] 用USB数据线插拔对照确定实际串口；记录端口和设备身份，不照抄其他电脑的端口名。
- [ ] 按[指南第3节](dht11-internal-lab.md#3-无硬件准备与离线构建)核对锁定依赖，在无`secrets.h`状态构建固件及LittleFS镜像，保存构建日志和两个当次SHA-256。
- [ ] 读实际`partitions.bin`；确认初始化镜像尺寸等于文件系统分区，镜像解包文件列表只有README且内容与`data/README.txt`一致。若布局不是当前4MB默认表，先复核配置。

**实际结果与证据：**未执行。

## B. 首次本地采集与文件系统（T1）

- [ ] 按[指南4.1节](dht11-internal-lab.md#41-确认串口和烧录)烧录未配置上传身份的固件，记录烧录日志、115200串口日志及启动时报告的版本、测试标记、GPIO与bootId。
- [ ] 记录首次有效帧是否只用于priming；继续观察新帧，保存逐次触发与读取日志、实际间隔、温湿度或`DHT11_READ_FAILED`错误阶段。不以串口数字证明精度。
- [ ] 仅在确认全新且无待保留请求的设备上，按[指南4.2节](dht11-internal-lab.md#42-首次文件系统初始化)上传一次LittleFS初始化镜像，保存端口、镜像hash和工具结果。已有或状态不明设备不执行`uploadfs`。
- [ ] 如无有效值，按卡C/D保留失败与接线证据；不填写虚构的“正常室温”。

## C. 测试平台真实接入（T2）

- [ ] 使用[内部测试准备说明](internal-lab-preparation.md)在明确的隔离数据库导入并发布**测试包**，建立管理员、学生、任务和真实硬件设备绑定；学生通过原接口创建活动会话。保存版本ID/hash、设备和会话标识；测试发布不写成正式知识发布。
- [ ] 核对后端地址可由ESP32访问，再按[指南5.2节](dht11-internal-lab.md#52-固件上传配置)在被忽略的`secrets.h`写入实际测试凭据；重新构建并烧录固件，另记新bin hash。普通固件更新不再次覆盖LittleFS。
- [ ] 启动后核对LittleFS可用，记录失败时的原始串口行；不自动格式化或反复`uploadfs`。
- [ ] 对照设备串口批次与后端实际接收：requestId、bootId/sequenceNo、会话、包版本、心跳、读数或失败日志、回执及入库记录ID。只有服务端记录可证明已入库。
- [ ] 核对设备时间是否可信；无NTP时如实记录服务端时间回退，不把接收时间写成测量时间。

## D. 单因素异常、恢复与缓存（T3 → T4）

- [ ] 先保存接线不变时的有效采样基线；断电后只断开DATA，重新上电，记录接线变化、供电和完整失败序列。核对当前规则所需的窗口累计5次是否命中，再记录后端证据及有限候选/unknown；读取失败不能单独确定是断线。
- [ ] 断电恢复DATA，重新上电并取得**新的**有效采样和上传记录，再按[指南第6节](dht11-internal-lab.md#6-重新检查与恢复判断)显式重新检查。保存前后诊断ID、Evidence UUID、窗口和结果；若恢复判据仍未知，就记unknown。
- [ ] 按[施工方案S5](dht11-hardware-execution-plan.md#8-s5断网缓存重连和重启保留)断开专用实验Wi-Fi，保持平台服务运行，记录冻结批次身份及本地状态；恢复网络后核对原requestId、回执和库中幂等记录。记录缓存占用时是否暂停采样、解除后是否重新priming。
- [ ] 未做的短写、挂载失败、重启窗口和掉电测试仍标未执行；按[硬件验证计划C-04至C-08](../hardware-validation-plan.md#8-两实验共用的离线与恢复测试)另开受控试验，不用这次断网结果概括所有故障。
