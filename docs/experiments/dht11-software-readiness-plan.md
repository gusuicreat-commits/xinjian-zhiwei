## 目标与边界

把当前DHT11资料包从“内容已写入、软件验证未收尾”推进到“软件检查通过，可按指南完成一次隔离环境的合成演练”。硬件、教学试用和正式知识发布继续分别验收。

当前基线：DHT11工作区2.0.8、固件0.2.4；已有大量其他未提交修改。实施开始先保存当时工作区文件指纹和必要原件，不能用HEAD覆盖现有修改，也不借用上一轮测试数量证明新改动。

分两轮交付：A轮解决构建和浏览器失败；B轮补平台准备入口与合成演练。无需等待硬件或教师联系；不更改规则阈值、诊断候选、采样语义、知识审核边界或历史快照。

## A轮：关闭已有失败

### SW-01：LittleFS镜像工具未取得

事实：构建配置已显式选择littlefs，固件编译成功；buildfs安装tool-mklittlefs时返回HTTPClientError，直接访问官方注册接口出现TLS连接错误，littlefs.bin未生成。网络或环境的具体原因尚未确定，不能认定是Python版本问题。

实施步骤：

1. 使用当前可用的PlatformIO/Python环境，记录平台、工具、主机架构和已安装包；复现最小下载请求，区分DNS、代理、TLS、注册元数据和实际下载地址失败。
2. 优先恢复官方分发路径。若需手动离线安装，只采用可核验的官方同版本、同架构产物，登记来源、版本、校验依据和安装方式；不关闭TLS校验、不把任意压缩包伪装成缓存，也不无依据升级整套依赖。
3. 重新执行固件与buildfs目标，核对生成的firmware.bin/littlefs.bin、目标分区配置和SHA-256。检查初始镜像内容来自data目录，仅含预定说明文件；不含凭据、待发送请求或测量数据。
4. 更新依赖取得说明和本轮构建记录；没有硬件时不执行upload/uploadfs，不宣称挂载或掉电验证通过。

影响位置：PlatformIO工具环境、必要的构建说明；仅在证据表明有配置缺陷时修改platformio.ini、verify.sh或CI。原有LittleFS.begin(false)与数据保留行为继续生效。

完成条件：锁定依赖可追溯，两个构建目标退出0，产物实际存在且身份已记录。若官方产物仍无法取得，保留该项受阻，并推进不依赖它的工作。

### SW-02：页面依赖外部字体导致资源失败

事实：frontend/index.html加载Google Fonts；日志和trace已捕获该URL的ERR_CONNECTION_CLOSED。Mock浏览器两轮均12通过、同5项失败，其中有资源错误和操作超时；不能把所有超时都归因于字体。

设计决定：本轮去掉页面启动时的Google Fonts请求，沿用现有系统字体回退。这样不新增在线安装依赖。若以后要求跨平台完全一致的字体，再单独引入有来源和许可证的本地字体资源。

实施步骤：

1. 保留原失败日志、请求URL及截图；核对正式构建与离线审阅构建是否共用index.html，定位全部同类外部字体入口。
2. 移除对应stylesheet与preconnect；仅在回退出现实际布局问题时调整必要样式，不顺带重做界面。
3. 在禁止外部网络、保留本地应用访问的条件下验证启动和刷新，确认没有Google字体请求，正文仍可读。
4. 复跑原5项失败及离线审阅用例，再执行完整17项Mock浏览器、8项真实后端联调和离线审阅检查。生产构建检查学生、教师、两个登录页、就绪页在桌面/平板/手机的溢出、换行与关键操作位置。

完成条件：页面不依赖外部字体即可使用；既有功能与布局检查通过。测试不能通过拦截后假装下载成功、过滤console错误或删除关键断言来解决问题。

### SW-03：操作与刷新超时

事实：有元素稳定性/操作等待超时；离线审阅页在第二次reload等待load时达到30秒上限。与字体故障可能有关，但根因尚未逐项确认。

处理顺序：先完成SW-02，再复现残余失败；按用例读取trace中的请求、导航、DOM状态和耗时，检查资源等待、遮挡/动画、轮询或组件状态。确有应用缺陷则修共同入口；若测试等待条件与实际业务就绪条件不符，先说明独立预期，再改为明确的页面状态断言。不得单纯加大超时或增加重试凑通过。

完成条件：每个原失败都有修复后结果；无法复现的标明范围，不能以一次偶然成功认定根因。通过后才关闭问题。

## B轮：补平台准备与无硬件演练

### PREP-01：内部实验初始化入口

事实：seed_demo创建未绑定当前DHT11包的演示任务，并直接生成会话；它不能作为本项目从空测试环境准备固定包实验的统一入口。现有包导入、状态转换和会话服务各自会提交事务，不能把它们外面包一层事务就声称全流程原子完成。

设计决定：新增通用的内部实验准备CLI与共同服务，首个配置用于DHT11。第一版不增加管理页面或通用课程管理API；不扩写旧seed_demo为隐式迁移工具，不在诊断引擎中硬编码DHT11分支。

实施入口为app.cli.prepare_internal_experiment，提供plan/apply/status三个操作：

- plan：只读检查明确选择的隔离测试数据库、前缀、操作者、包版本ID/hash和对象冲突，输出将创建或复用的对象；不自动使用业务DATABASE_URL兜底，不在只读模式创建角色目录或生成凭据。
- apply：要求操作身份具有管理权限，目标包是明确选定、当前可用于新任务的已发布测试版本；建立测试课程/班级、测试学生与教师身份、成员关系、实验任务及设备绑定。学生、教师角色只代表软件测试身份。
- status：只读列出对象ID、包hash、阶段完成状态与下一操作；不返回已有令牌或重新发布包。

包导入和状态转换保持独立步骤：通过现有管理员接口在专用测试环境显式执行validate/import以及既有状态流转。初始化CLI不代为审批或把本地草稿直接标published。单人维护者可完成测试环境的管理操作，记录实际软件自审依据；不得伪造教师确认或把测试发布称为正式知识发布。

从空库开始的操作说明覆盖：准备隔离库及现有迁移、创建测试管理员、导入并管理测试包状态、plan/apply、学生登录、用现有start_session创建会话。初始化CLI不直接插入活动会话，确保权限、设备占用与固定版本由现有会话服务决定。

数据与恢复设计：

1. 输入显式前缀、包身份及目标测试库；测试标记保守传播。设备凭据与账号密码通过交互或本地受限输入取得，库内只存哈希，常规日志与结果清单不输出明文。
2. 一次apply内的课程、班级、身份、任务、绑定和成功审计在同一数据库事务提交。使用前缀事务锁配合既有唯一约束，在锁后重验操作者、包状态和对象关系；不改造包发布服务的既有提交行为。
3. 同前缀、同身份和同配置重复调用返回既有结果，不重置密码/令牌、不重建任务。前缀冲突、部分历史对象、不同包hash、正式对象混入均拒绝，不自动补丁式接管。
4. 提交前失败应无半套新对象；提交成功但清单写盘/响应丢失，通过同参数status或重复apply读取结果。只读结果由库内关系与审计重建，文件不是唯一成功凭据。
5. 测试阶段清理限定本轮专用容器/随机schema；可持续的内部测试环境保留历史记录，代码回退不删除会话、证据或已发布包。

实施前新增独立反例：无权操作者、草稿/撤回/过期包、错误hash、对象冲突、重复与并发apply、提交前故障、提交后响应丢失、密码不重置、旧会话不改版。用真实PostgreSQL验证锁和事务，用服务/API验证学生会话固定版本；未设计新字段，不预设数据库迁移，发现必须新增约束时补充具体迁移设计。

完成条件：干净的隔离环境能经文档入口建立可见的授权任务；学生从现有接口开始会话并固定正确包版本；重复执行无重复对象和凭据重置，失败无部分提交，旧对象不被改写。

### DRILL-01：按指南进行合成演练

使用PREP-01建立对象，经现有设备批次入口写入明确的合成记录，走真实API、数据库和浏览器；AI默认关闭，必要的Provider回归单列为Mock。

演练覆盖：无数据、有效温湿度/心跳、读取失败累计达到当前规则条件、缺测/旧数据、错误设备或会话、重复批次、查看资料与反馈、新记录重新检查、结束会话。预期来自既有规则和独立测试材料，不由新初始化程序生成“标准答案”。

每个场景保存设备/会话/固定包身份、requestId、实际记录与诊断、资料快照及前后对照。参数不足时unknown是允许且必要的结果；不得填入未经实测的时限来让页面显示正常。合成设备与未来真实板卡使用不同身份，不能将合成日志记到实物设备履历。

完成条件：指南里的每项软件操作能找到真实入口，预期与实际一致；修改正文时同步来源hash、包版本及清单，新指导取新快照，旧指导保持不变。真人可用性仍未验证。

## 版本、验证与交付

- A轮只有环境依赖恢复时不虚增固件/包版本；如修改固件配置或受登记的源码，再按版本规则升级。前端行为改动按应用版本政策核对，不预先硬填版本号。
- B轮如更新被content_registry引用的实验指南，必须同步指南来源hash并升级DHT11包；不能只更新hash沿用已交付2.0.8。LED未受影响则不改。
- 每轮先运行与改动相关的原反例和正常路径；B轮整链交付在最终源码上执行scripts/verify.sh，使用明确的隔离PostgreSQL与工具环境，不加--docker部署参数。A轮、B轮结果分别绑定自己的源码指纹，不拼接历史通过数量。
- 同步API/模块契约、操作指南、评测入口和当前状态；仅在新增业务规则时补开发准则对应表，不另写平行规则。
- 每轮报告保存于独立日期的output/audits目录，包含修改前证据、实际差异、命令/退出码、界面材料、撤回方式及未验证范围。受阻依赖与业务断言失败分开报告。
- 此方案完成后可称“软件演练已验证的内部测试资料”；仍不能称硬件、真实模型、课堂验收或正式发布完成。
