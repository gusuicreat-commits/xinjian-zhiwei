## 1. 目标与实施组织

目标是补齐共享规则在最终写入、外发、恢复及展示时的执行，而非逐文件打补丁。固定 LangGraph、确定性诊断、AI 默认关闭、已有请求回执恢复与审核边界继续保留。本方案不引入 RAG、自由规划 Agent、自动硬件操作或新的模型服务。

## 3. G1：同一个人、同一时刻、同一套授权

### 修改位置与时序

- `services/auth.py` 继续唯一维护 `ActorContext/current_actor/authorize_actor`。记忆影响复核要求当前 `intervention.manage`、teacher/admin 与已持久化诊断范围；维护清理要求当前 admin 和 `user.manage`。这两项能力分别沿现有角色能力收敛，不把管理员清理权限授予普通教师。
- 检查 `memory_governance.py` 的影响列表/复核、清理计划创建/执行、来源缓存清理及导出入口。公开命令必须接收服务器构造的身份；不能保留“路由检查过就可以”的无身份写入口。已有来源停用 outbox 若为系统执行，明确独立内部入口、已提交事件和用途，不能让客户端借用为免鉴权通道。
- 最终短事务遵守现有锁序：领域资源锁 → 当前用户 → AuthSession → 角色和权限关系 → 范围依据。先画调用链与撤权锁序，避免局部反向加锁。权限不足、会话失效分别保留 403/401；记忆路由的通用 `PermissionError` 映射不能吞掉 401。
- 增加撤销当前登录会话的 `DELETE /api/v1/auth/session`。由持有 token 的请求撤销该 token 对应会话，不接受任意 session_id；只在首次撤销时写一条安全审计。token 缺失/无效返回 401；同一已撤销或已过期 token 可返回无正文的幂等成功，不开放其他业务权限。此专用令牌解析不能替换正常鉴权。
- 会话撤销按同一 user → session 顺序取得必要锁。动作先受保护提交则是合法历史，撤销先提交则后续动作拒绝；不承诺撤销能取消已经提交的行为。

### 前端与登录

把 `teacherSession.ts`、`studentSession.ts` 当前共用的 `logout()` 拆为本地状态清理与用户主动退出。逐个核对登录初始化、401、选择实验、结束实验、页面退出的调用方：内部清理不误撤销新 token；用户退出捕获原 token，立即隔离旧页面和在途结果，再调用服务端撤销。请求失败仍清本地，并明确提示“本机已退出，服务端退出未确认”，不显示完全成功、不永久保存 token 以便重试。切换账号时仅清理/撤销旧身份，迟到登录结果不得留下新发但无人使用的有效会话。实验结束的原有界面行为保留，账号撤销必须由明确的退出动作触发，不能由恢复查询误触发。

设备演示凭据不是 AuthSession，离线审阅模式不访问后端。相应退出仍按原模式清理，不把设备 token 当作个人会话撤销。

失败登录使用与当前密码策略一致的固定 dummy hash 验证路径，避免请求内生成 hash；停用用户也不在计算前短路。继续使用现有数据库登录准入/限流，不用延迟 sleep 假装恒定时间。旧密码 hash 保持可验证；不同历史工作因子造成的残余差异另行测量，不能用一次耗时断言证明不可枚举。本轮不夹带密码算法迁移。

### 验收、兼容与撤回

覆盖两端主动退出、重复点击、网络失败、跨标签旧 token、新登录迟到响应、退出与复核/清理的两种事务顺序。检查响应、AuthSession、审计、缓存删除与实际页面。保留原 AuthSession 历史，不全量撤销其他设备。失败回退时保留已撤销状态；不能回退到无服务端撤销的旧前端并继续宣称退出已生效。可临时关闭受影响管理动作，保留正常规则诊断。

## 4. G2：知识工作区从共享密钥转为个人与资料授权

这是本轮一项明确的访问合同变更：现有 API 文档承认共享工作区边界，不能只换依赖而不迁移调用方。

- 在 `services/rbac.py` 沿用 `knowledge.organize` 和 `knowledge.review.approve`，分别要求整理者和正式批准者身份。`user.manage` 只允许管理授权，不自动取得整理或批准能力。
- 采用 source 级显式授权关系，document/chunk 从数据库沿外键解析 source，不接受客户端自报归属。拟新增授权表以 `(source_id, user_id, capability)` 唯一，记录授予/撤销审计；索引覆盖按用户列出来源与按 source 校验。新来源由当前整理者创建，自动获得该来源的整理范围；批准者须具备独立的 review 范围和全局批准能力。
- 授予/撤销范围通过有 `user.manage` 的管理员入口，限定具体来源、目标个人与能力，并复用最终授权。全局知识角色不能授权自己访问所有来源。source 原有 `authorization_scope` 是资料使用许可文字，不可直接当用户 ACL。
- 列表、统计、来源登记、文本/文件导入、workspace 读取、chunk 修改/拆分/合并/删除、文档审核统一接入。列表按授权过滤，统计不泄露未授权总量；游标基于授权查询并有上限。单对象越界使用统一不披露对象存在性的响应策略。批量操作先检查全部对象，失败不部分写入。
- 解析文件等耗时工作前预检，完成后锁定 source/document 等对象，再调用 G1 与来源范围校验后落库。同时核对来源范围撤销、全局权限撤销与资料状态变化。正式审批继续禁止自行批准；提交人以服务端个人身份记录，不能信任客户端 `organizer_ref`。

**历史与兼容：** 追加授权关系迁移，不给旧来源猜测所有者或班级，不将全体整理员自动加入旧来源。旧来源保留全部内容、版本和审核历史，初始无新工作区授权；管理员只查看受限迁移清单（ID、标识、授权状态），显式分配并留审计。旧提交人无法可靠映射时不能绕过自审限制，应由当前整理者核对并重新提交，追加新记录，不重写旧审核。既有诊断对已审核、适用资料的受控读取仍按原来源/版本合同运行，工作区 ACL 不冒充诊断可用性判断。

`X-Review-Token` 单独访问在所有环境均不再放行工作区；本轮不保留静默的 token-only 后门。扫描现有 CLI、示例、测试与任何客户端调用，迁移到个人会话；更新 API/部署文档和新权限管理用法。正式案例审核已有个人权限保护，保留并补相邻回归，不当成全新功能重写。

**验收与撤回：** A/B 整理者、独立批准者、管理员四类合成身份；每类接口检验角色与 source 范围组合，以及等锁期间撤权。测试历史库升级后资料/审核记录数量与内容不变、旧来源默认受限、合法授予后可恢复工作。回退优先关闭工作区写操作，保留新表与审计；不得为了兼容旧代码恢复共享 token 写权限或删除 ACL 表。

## 5. G3：从外发到展示保留事实等级

### 外发清洗（问题 2）

在 `context_sanitizer.py` 统一遍历动态键和值，核对推理、解释、案例润色及模板 `metric_ranges` 等调用路径。合法指标名不能因通用替换变成另一个键；敏感键的可选内容按完整上下文单元省略并记录固定原因，必需引用/标识冲突则取消本次增强。禁止清洗后键碰撞、偷换 evidence ID 或将秘密误当安全 ID。测试应捕获真正交给客户端的最终 messages，而非只断言中间 helper 输出。

### API 与页面语义（问题 5、8）

`ai/output_contract.py` 根据已校验的支持等级、证据和允许动作生成当前推理摘要；模型自由摘要不能直接覆盖它。`current_advice.py` 统一组合交付资格和这份安全投影，再由工作流、仪表盘、解释 API、缓存命中和恢复返回复用。不能只修 Vue 或只修新生成记录。

保留 `missing_evidence` 兼容字段，其模型来源项明确为“建议核验/尚未确认”；实际已证实缺失的事实只能来自确定性证据，分开投影。页面使用来源和状态决定文案，不通过搜索“缺少”等词猜测。教师明确审核后的允许编辑结果按现有教师权限与来源展示，不因为禁止模型自由摘要而抹掉教师合法意见。

旧调用记录、Checkpoint、缓存中的原始模型输出不回填为新事实；读取当前建议时重投影，无法确定新合同所需信息则取消 AI 增强、保留规则结果。历史受权审计可以保留当时原输出，但明确来源和历史身份，不进入当前学生建议。只有语义合同真正变化的 Prompt/输出合同版本升版；缓存指纹纳入有效版本，包内容未改不刷包版本。

**验收与撤回：** 输入键/值秘密、注入语句、unknown、冲突、正常候选、有/无教师确认、旧缓存/旧 Checkpoint 全覆盖。检查最终 API、数据库保留的历史与实际页面三者，核对没有额外 Provider 调用。回退时关闭 AI 当前展示或采用规则投影，保留历史，不恢复自由文字当事实的旧投影。

## 6. G4：一次逻辑操作与每次物理请求分开记录

### 持久化与恢复（先处理问题 4，再接重试）

保留 `AIUsageReservation` 的“一次物理尝试一份预留”；拟增加持久逻辑操作及尝试关联，避免用 `AICallRecord` 的事后唯一约束冒充发送幂等。

- 操作键由服务器提供：工作流阶段使用 workflow + 阶段；非工作流解释使用持久诊断/请求身份；案例润色使用草稿 ID + 被核对的版本 + 动作身份。分别登记入口，不用可变正文或单一 diagnosis ID 混淆不同动作。
- 每个逻辑操作冻结输入指纹及 Provider/模型/Prompt/Schema/验证器等执行版本。键上唯一约束，指纹作为冲突检查，而非更换指纹即可重新调用同阶段。合法的新业务版本必须形成明确新操作，不能恢复时静默换模型或输入。
- 状态建议为 `prepared → dispatching → succeeded / failed_known / outcome_unknown`。`dispatching`、尝试号、额度预留在发送前同一短事务提交；不持数据库锁等待 Provider。操作结果、调用关联与可重放状态在返回后尽可能同事务提交，再推进图的 Checkpoint。
- 只有 `failed_known` 且重试政策允许时，才在原操作内增加尝试号并再次进入 `dispatching`；`succeeded` 只重放，`outcome_unknown` 不自动返回可发送状态。各状态转换用条件更新及数据库约束保护，不能先无锁判断再发送。
- 并发恢复只能有一个发送者；其他请求复用已完成结果或获得“处理中/待核对”，不得抢到过期租约就再次发送。接收后崩溃、读超时、返回后保存失败，以及无法判断是否已发送的 dispatching 均转为未知或保持可识别的在途状态，禁止自动重发/退款。允许损失一次增强而保住确定性流程。
- 结果重放重新检查当前权限、来源和版本。可信的 Provider 幂等键/结果查询将来可接入，但本轮不假定兼容 API 支持，不能承诺外部 exactly-once。未知费用继续保留原预留与待核对状态。
- 旧 unresolved 预留缺少操作身份时不能猜测归属、自动退款或直接重发；关联明确的阶段阻止重发，关联不明的旧诊断保守停用该次增强。旧成功结果可走现有资格重验。可枚举受影响 ID/原因供管理员核对，历史费用记录不改写。

数据库变更只追加迁移，操作唯一键与查询索引覆盖阶段重放、尝试归属和未知状态查询；不用第二个费用总账重复存余额。还要核对业务库与 Checkpoint 跨库恢复：结果已在业务库提交、Checkpoint 未推进时只能补进度，不能再收费重调。

### 传输与重试（问题 3、7）

`clients.py` 的一次调用只执行一次物理请求。同步对外接口可以保留，内部须选用可取消、能关闭连接的受期限传输；不能用 `Future.result(timeout)` 后放任线程继续请求。总 deadline 用单调时钟覆盖连接、发送、读取、重试等待及 JSON 解析，剩余预算向下传递；既有单次超时继续作为单次上限，新增每逻辑操作的总上限。冻结持久到期时点用于重启恢复，不能每次恢复重置预算。

响应使用限量读取，对编码/解码后体积及解析成本设边界，不仅信任 Content-Length。压缩响应须受控解压；若暂不支持有界解压，则请求 identity 并拒绝意外编码。超限关闭响应并走安全降级，不把异常正文写入日志。

结构化异常只携带安全状态码、固定原因、是否能确认未发送、允许重试时间和结果是否未知。统一政策如下：

| 情形 | 同操作处理 |
| --- | --- |
| 400/401/403/404 等确定配置/权限/请求错误 | 不重复同一无效请求，降级并记录固定原因 |
| 429 | 解析秒数或 HTTP 日期形式 Retry-After；不能等待到该时点则直接降级，不能截短后提前重试 |
| 明确未发送的连接失败 | 剩余次数、总时间及预算允许时有限退避；每次重试重新准入 |
| 502/503/504 等服务错误 | 不一律视为“肯定未执行”；按传输与 Provider 合同判断。无法证明执行结果时归入未知，不自动重发 |
| 已收到完整但结构/语义不合规的结果 | 标记已完成尝试并计费；按现有有限输出重试策略及剩余预算决定下一次，不无限自修 |
| 发送后的超时、连接中断、响应截断或保存失败 | 结果/费用可能未知，禁止自动重发；确定性降级或恢复已保存结果 |

Retry-After 缺失或非法时使用有限退避；所有等待都不能突破逻辑操作 deadline。保留请求级 request_id 与前端现有回执查询；前端 8 秒超时仍可进入“结果待确认”，不换身份重提。总时限只限制 AI 增强，不应取消已经完成的规则诊断。

**验收与撤回：** 在预留前、发送前、服务端接收后、结果保存前/后、Checkpoint 保存前后分别中断，检查物理请求数、预留、结果及恢复页面。使用隔离 PostgreSQL 两进程和本地可控 HTTP 服务测试竞争、滴流、压缩体、429、不可重试错误。回退时关闭 AI 并保留操作/费用记录；旧代码不认识发送状态，不能直接回滚后继续开启 AI。

## 7. G5：上传、解析、落库使用贯通的预算

保留现有 Base64 JSON API，避免修复体积边界时顺带重写上传产品流程。现有 10 MiB 原文件和 500,000 文档字符上限继续作为默认业务边界；编码长度按 `4 × ceil(file_bytes / 3)` 计算。元数据另设有界预算，请求体上限由编码上限与元数据预算导出，不能直接把原文件上限照搬到 Nginx。

- 配置负责预算；应用在 JSON/Pydantic 解析前按实际收到的字节计数，Content-Length 只作提前拒绝提示。缺长度、chunked、伪造长度、断连均处理；超限 413，不缓存完整超标请求。认证与资源范围应尽可能在重解析前完成。
- Nginx 使用由部署配置生成的对应上限，并在隔离代理集成中核对有效值；不能在 Python、Compose、Nginx 各维护不同默认。只调整相关知识导入路径，不放宽设备已有流式上限。Schema 与服务入口保留二次防线，CLI 也使用同一解析预算。
- PDF 不再一次性抽取所有页。文件解析在可终止的隔离子进程执行，父进程负责期限和进程回收；子进程只接收文件与预算，不接收数据库连接、Provider 密钥或学生身份。输出 IPC 本身有体积上限。
- 解析预算至少覆盖页数、输出字符/字节、CPU、内存、墙钟时间与并发子进程数。页数/累计输出限制用于尽早退出，操作系统进程资源限制兜住解析器内部先分配的大块内容；单纯改成 generator 或线程 timeout 不足以完成修复。DOCX 原有 XML 上限保留，同隔离边界覆盖 ZIP 目录解析及 CSV/TXT 的展开处理。
- 新 CPU/内存/并发默认值在实施时用项目正常资料集和高展开反例测定并记录为**软件配置预算**，不冒充课堂容量/SLO。资源限制无法有效执行的平台明确禁用相应文件解析，不静默回到进程内无限制模式；Linux 容器和本机支持范围均需实测后写入部署文档。
- 预算定值属于 G5 修改前的必做探针：先记录正常样本的页数、展开量、峰值内存与耗时，再选有限配置并验证超限反例；将最终数值、平台和覆盖样本写进实施记录。在此之前不能把“已设计资源限制”当作该组可交付。
- 超体积/展开预算返回 413；不支持或坏格式返回 422；并发解析容量耗尽返回明确可重试的服务错误。失败只保留安全原因，不保存半份来源内容。解析结束后调用 G2 的最终授权，再按原内容哈希幂等导入。

**验收与撤回：** 通过真实隔离 Nginx → 应用测试合法大文件、上限与上限加一、Base64 膨胀、畸形 JSON、慢请求、中断、PDF 展开、解析进程超限退出和恢复后的正常导入；检查峰值资源及无孤儿进程。坏文件不能拖垮其他正常请求。未确认平台资源限制有效时不把本组标为通过。回退可关闭文件导入、保留受限文本导入；不能为了恢复功能取消进程限制或只调大代理上限。

## 8. G6/G7：配置失败要显式，异常也能追查

**问题 12：** `app_env` 规范化为 development/test/staging/production，保留已用的 `prod → production` 明确别名；空值、`prd` 等未知拼写拒绝。工作流开启时仅 development/test 可以使用内存 Checkpoint，staging/production 必须满足持久配置；工作流关闭不人为增加数据库依赖。更新 Compose、示例、CLI 与部署文档，检测非法环境应发生在外部 I/O 前。回退配置可使用合法环境与持久模式，不改写为 development 绕过保护。

**问题 14：** Python Settings 保留唯一默认，Compose 不再注入自己的旧默认。显式 Prompt 版本覆盖保留但必须能追溯到有效 Prompt 与内容 hash；G3 若改变实际语义，同步合同版本和缓存指纹，不只改显示标签。测试两种无覆盖启动配置及显式覆盖，不打印完整 Compose 配置以免输出密钥。历史调用版本不回填。撤回时继续使用一致的已知版本和内容 hash，不回退到混用默认。

**问题 15：** 请求进入时生成/校验有界 request_id，由最外层 ASGI 响应封装覆盖正常与异常响应；未处理异常使用安全 JSON 和固定错误码，不输出原异常文本。核对 FastAPI/Starlette 外层错误处理中间件顺序，不能只在现有 `call_next` 后补代码。保留现有 401/403/409/413/422 含义，错误日志只记请求 ID、固定分类和必要去敏信息；已发送头的流式响应只能结束连接并记失败，不能伪造第二个成功响应。回退可保留最小安全兜底，不取消 G1 的认证错误语义。

### 必须检查的交接与迁移

1. 用户主动退出与正在等待的复核、文件解析后提交、AI 返回交付交错；撤权先提交则不能新增受保护业务效果。
