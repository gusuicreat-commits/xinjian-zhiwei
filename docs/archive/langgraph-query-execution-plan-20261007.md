## 1. 要解决的问题和本轮边界

目标：验证在原有诊断之前增加**有边界的资料查询与一次许可追问**，能否取得更多有效证据、减少无效追问，并改善学生下一步指导。服务于[PRD](../product-background-prd.md)的 FR-04–FR-06；缺少真实采集能力的信号仍是未知，本方案不实现新的硬件观测。

下一轮交付隔离评测原型、测试、配对结果和采用建议。先做 A/B0；不预设 Agent 一定有效。

| 对象 | 本轮处理 |
| --- | --- |
| A：现有固定诊断流程 | 冻结真实代码、配置与输出合同，作为基线；不能用新写的简化规则冒充 A |
| B0：LangGraph 受控查询 | 复用现有依赖、JSON 调用治理、来源与诊断服务，新增少量取证节点 |
| 确定性查询策略 | 与 B0 共用任务合同，作为辅助对照；用于区分模型选择的收益，不能替代 A |
| B1 原生工具调用、PydanticAI、Pi | 暂不实施；只有记录明确能力缺口后再提出针对性的备选实验 |
| 产品 API、Vue 页面、部署和正式迁移 | 后续采纳阶段；本轮不接入产品、不改变 AI 默认关闭 |
| RAG、向量库、多 Agent、自由代码或硬件执行 | 无对应本轮需求，不增加 |

B0 的模型只选择服务器给出的合法动作，使用 `complete_json`；报告明确这是 JSON 动作选择，不是原生 function calling。无选择空间时直接执行确定性分支，不为制造 Agent 轨迹而调用模型。

## 4. 任务合同先于图实现

### 4.1 服务器拥有的对象

- `TaskScope`：任务、操作者身份引用、实验/组件/会话、诊断、固定包版本、输入材料修订及合同版本。身份由运行时服务注入，不接受模型指定用户、课程或来源范围。
- `Requirement`：需要回答什么、哪些来源类型与值能满足、时效/适用条件、可查工具、许可问题。条件必须来自独立业务预期，不从模型输出生成。
- `EvidenceRef`：稳定来源身份、来源类型、材料修订、适用范围、测试性质、完整单元的指纹和受限投影。报告、配置比较、独立测量分别保留类型。
- `Action`：在服务器生成的 `eligible_actions` 中精确选择；禁止额外字段。允许查询、许可提问、提议合法终态，拒绝任意 URL、路径、SQL、身份覆盖及自由动作。
- `Question/AnswerReceipt`：任务、需求、问题与目录版本、提问时修订、答复请求 ID/内容哈希、来源类型及消费状态。公开回执不含受限原文。

前述字段是设计合同，不是声明现有 API 已支持。持久化前逐项确认唯一生产方和旧记录兼容性。

### 4.2 先修正旧原型可能混淆的语义

旧 `query-task-v2` 必须复查并通过独立反例后再迁入：

1. **配置不符与证据冲突分开**：一条合法 `mismatch` 比较结果可以满足“查明配置是否一致”的取证需求；不表示材料互相矛盾，也不自动确认唯一根因。
2. **收到答复与满足需求分开**：`unclear`、“不知道/无法观察”关闭本题，通常仍保留目标观察缺口；不得仅凭记录存在将其记为满足。
3. **来源去重与文本去重分开**：同来源同修订换 ID 不算新进展；独立来源同文应保留。身份相同但内容不一致拒绝整批写入。
4. **任务完成与故障解决分开**：`completed_satisfied` 只说明取证需求满足；规则、候选、输出验证和根因确认职责继续由原有模块承担。
5. **过期与新答复分开**：普通外部修订变化使旧任务停止；合法答复沿专门事务创建后继输入修订并绑定原问题，不能简单把版本检查关闭，也不能把所有新答复一概判为 stale。

材料状态维持 `not_checked/present/checked_empty/conflicting/stale`，另记录固定的缺口原因（如 `observation_unknown`）。`present` 必须满足对应 Requirement 的实质条件。语义调整升合同版本，保留旧反例；旧快照不可无声按新合同继续执行。

### 4.3 资格、进展与终态

先检查当前有效材料；充分时结束取证。材料不足先查许可存档，查不到或仍有待澄清冲突时才考虑许可问题。同需求同修订已有 pending/answered 问题不重问；一道新问题用尽后仍不足则保留未知。

有效进展是需求状态实质改变、取得合法新观察或澄清冲突；工具次数、别名、新措辞不算进展。非法模型动作立即转确定性策略，不额外调用模型纠错。工具故障不得伪装成查无数据；权限拒绝不得通过备用工具继续访问。

终态沿用总体方案，分别记录 satisfied、unknown、资源停止、无进展、失败、撤权、过期、取消及外发结果未知。资源额度耗尽不算“正常完成”。终态写入和交付前再次重算范围、证据和完成条件。

## 5. 图、工具与答复恢复

```text
装载任务并校验 → 计算缺口/合法动作 → 唯一动作直接选择或受管模型选择
                    ↑                          ↓
                 整批校验并入证据 ← 受权只读查询
                    ↑                          ↓（需要许可追问）
        校验答复回执并采用后继修订 ← interrupt 等待答复
                    ↓
          合法终态 → 原诊断流程 → 当前权限/来源下的交付投影
```

图的终止条件由任务合同返回；LangGraph recursion limit 只是最后一道运行保护，不作为业务预算。

工具限定为本任务证据、绑定版本的包要求、通过授权/审核/适用性筛选的案例。每个工具先查真实服务是否已有能力；没有真实生产方则输出明确缺失，合成适配器单独标记。不能把模型任意 ID 翻译成通用数据库查询。8 KiB 投影按 UTF-8 序列化后的字节检查，整单元入选；超量明确 omitted，不切断为伪完整证据。

执行入口、工具前后、锁/退避等待后、模型外发前后、答复提交、恢复、缓存回放及最终读取都验证权限和来源。撤权结果不透露受限对象是否存在；敏感旧 checkpoint 不能因其已保存而被直接展示。

### 恢复和存储的最小做法

1. 单元层使用内存 checkpointer 验证图路径，明确不证明持久恢复。
2. 存储层使用专用测试 PostgreSQL 和官方 saver；连接重建与真正进程终止分别测。任务/问题/答复的业务回执不能只依赖 checkpoint。
3. 先查现有模型能否表达新答复；不能表达时只在评测专用 schema 增加最小试验表，不修改已发布迁移、不连接业务库。记录这是试验实现，不能声称已具备产品恢复能力。
4. 提问登记节点与 `interrupt` 节点分开；登记以任务＋需求＋问题版本＋修订唯一。中断节点重执行不会重新提问、扣预算或调用模型。
5. 答复落库、pending→answered、后继修订及待恢复标记同一事务；同请求同内容返回原回执，同请求异内容拒绝。消费者按 revision 条件更新一次采用；暂停/恢复所有者由服务器校验。
6. checkpoint 与业务回执不假设跨库原子提交。重启后按业务回执核对已完成动作，再恢复图；回执已提交但 checkpoint 未保存不得二次消费，反向不一致停止并报告。
7. 模型操作身份在发送前固定，恢复查已有 AIOperation：成功可经重验回放，dispatching/outcome_unknown 不自动重发。不要用新随机键绕过旧请求未知状态。
8. 本轮采用同步调用和明确的单任务执行协调，复用现有锁/回执。必须测试并发恢复的排他性；锁不覆盖人工等待或网络等待。若无法用现有机制表达，先记录具体缺口并补最小适配，不直接建设队列/租约平台。

## 6. 调用治理和统一资源配置

所有真实请求经过 `GovernedAIInvocation`，包括选择、推理、解释。现有治理依赖诊断记录与持久化数据，评测须建立合法合成关联，不能绕过外键或用 DB-less 客户端代替。

在唯一评测 profile 中冻结以下上限；既有配置更严格时取更严格者。任务累计量从持久化操作/步骤核对，恢复和进程重启不清零：

| 项目 | 起始上限 |
| --- | --- |
| 查询选择的模型尝试 | 3 次，失败和实际重试也计入 |
| 全任务模型尝试 | 5 次，含最终诊断推理/解释；每次外发原子预检，不能用 3+5 分开计算 |
| 业务只读查询 | 4 次，顺序执行；失败查询计入，完成回放不冒充新查询 |
| 新提问 | 1 个；模拟答复、重启、恢复不增加额度 |
| 单次工具投影 | 8 KiB；完整单元与明确省略状态 |
| 模型输入 | 当前配置预算，现有默认 10000；完整消息与合同开销纳入，显式低限保留 |
| 活跃执行时间 | 累计 120 秒；含执行/锁/退避/模型等待，不含学生等待；异常退出保守计入未结算执行段 |
| 真实模型并发 | 1；并发边界用隔离库与替身测试 |

人工等待不持锁；到期机制必须明确。首轮每个评测任务设置显式 `expires_at`（评测 profile 可设创建后 30 分钟），过期不再采用答复；此值仅用于合成试验，不成为产品课程时限。活跃段使用单调时钟测耗时，持久化累计量与绝对到期；跨进程不能恢复旧 monotonic 数值作为当前时钟。

持久化总尝试限制若现有治理不能表达，先补共用预检接口与并发测试再真实外发，不在选择器里维护另一套人民币账本。费用预留、结算、失败及未知结果继续归现有治理所有。

真实 API 使用已有 `kimi-k2.6` 配置，只发送合成材料。原 ¥10 是历史总授权，**不能当作本轮新增 ¥10**。先核对授权范围、此前实际支出、未结算/在途预留及可确认余额，再决定配对批次规模；无法确认余额时完成离线交付并明确真实模型阶段受阻，不猜消费金额、不读取聊天中的旧密钥代替配置。调用前核对当时官方模型/价格与实际计费单位并记录来源；令牌估算不冒充账单硬上限。

## 7. 公平评测设计

### 7.1 三个问题分开回答

| 问题 | 对照方法 |
| --- | --- |
| 多取得信息是否有用？ | A 用原始合法材料；B0 通过许可工具/答复获得材料。差异属于整体增强收益，不全部归因于模型推理 |
| 模型选动作是否有增益？ | B0 与共用合同的确定性查询策略比较，工具、答复脚本、初始材料和限额一致 |
| 相同证据下 AI 是否更好？ | 将冻结后的相同合法材料回放给原诊断的规则模式与规则＋AI 模式；逐例比较合法指导与未知处理 |

A 的适用结果可以是资料不足；它没有新追问能力不记为崩溃或协议错误。所有组使用相同模型版本及末端合同，组间不能共享模型缓存或按最终答案给其中一组额外提示。查询策略选择效应和实际材料差异单列，报告不得宣称一次 A/B0 证明 LangGraph 优于 Pi。

### 7.2 样本冻结

先 12 个开发情境，再 24 个保留情境（8 类×3），每类须包含独立业务预期和合法对照：充分材料、工具可查、需补答、已答/无法观察、冲突/过期/不可区分、身份/来源变化、失败/资源边界、注入/越界。

固定模拟学生答复与工具材料；模型只能看到当前许可可见信息，不能读预期答案、评分标签或未来答复。情境/模板家族分离；调参用过的保留样本转开发集并补充保留集。旧失败作回归，不冒充新独立样本。教学题的语义金标准需有材料依据；未独立审阅的标记 provisional，不能算教师验收。

真实调用顺序：少量 JSON 选择兼容探针 → 完整配对开发批次 → 冻结后保留集。计划每组每情境重复 3 次，额度不足则减少完整配对批次并报 incomplete。不以大量重复挤占全部类别覆盖，不挑成功样本删失败；无足够预算时不给整体胜负结论。

### 7.3 必测反例与可观测结果

| 测试组 | 关键反例 | 应检查的实际结果 |
| --- | --- | --- |
| 合同 | 配置 mismatch、unclear、同源别名、独立同文、同身份异内容、混入错任务一行 | 状态符合独立预期；整批拒绝无部分采纳；根因未被确认 |
| 资格 | 有存档仍追问、跨实验问题、无批准目录、重复问、提前 finish | 非法动作无副作用；合法查询/未知路径仍能运行 |
| 权限与来源 | 等待中撤权、查询中来源撤回、外发后撤权、旧缓存/终态读取 | 禁止请求实际次数为零或已有在途明示；失效结果无交付、无泄漏 |
| 恢复 | interrupt 重入、双进程同答复、异内容重复、乱序/旧修订、丢响应 | 唯一回执、一次采用、累计预算一致，合法新答复能恢复 |
| 持久化故障 | 外发前后、答复提交后、checkpoint 保存前后终止进程 | 成功回放不重计费；未知调用不重发；状态可核对 |
| 资源 | 第 4 次模型选择、第 6 次全任务尝试、第 5 次查询、超量、过期、取消 | 到边界禁止下一副作用；实际尝试/预留/终态一致 |
| 注入 | 工具材料中的指令、伪造身份/路径/URL、模型额外字段 | 仅作为数据；无新工具、无范围扩大、无提示/答案标签泄漏 |
| 原有设计 | CoT 配置与审计、固定图反馈、整单元上下文/来源清单、案例适用、三类记忆生命周期、包引用、输出及预算 | 按影响复用既有测试；列出实际覆盖，不遗漏或全部一笔标通过 |

实质缺陷遵循“失败反例→根因→修复→重验”，相邻入口共享保护。关键反例至少观察外发次数、落库变化和交付内容之一，不只检查异常字符串。隔离破坏测试只针对重要守卫的有效性；不为文档改动增加测试。

离线先运行本次 contract/graph 测试，再运行涉及的治理、来源、恢复和上下文回归；PG 用项目明确的测试 DSN，不继承业务 `DATABASE_URL`。具体命令在实现后写入 `docs/evaluation.md`，不能将本方案拟建 CLI 写成目前可运行。若修改共同生产服务，增加对应反例和受影响回归；扩大为整条交付才执行必要完整门禁，纯评测新增不无目的重跑硬件/前端。

报告目录建议 `output/audits/langgraph-query-b0-<实际日期>/`，保存脱敏 Markdown/JSON、源码/配置/数据指纹、逐例配对结果、操作回执引用、实际费用与未执行项。实现代码与夹具进入版本控制，自动报告遵循[报告约定](../test-reporting.md)。报告退出 0 只表示指定软件断言通过；语义未审阅维持 `not_run/null`，总体不得冒充全面通过。

选择原则：先满足必需的授权、来源、恢复、资源和未知表达要求；再比较有效材料、有效下一步、无效追问、耗时/费用及维护增量。任何关键违反不能用平均分抵消。无稳定收益或证据不足则保留原方案；只有明确的可复现缺口才推进另一框架。统计样本小或人工语义未审阅时，不能声称诊断正确率显著提升。

隔离撤回只停用本轮评测入口并保留必要取证，不删历史、不回退其他修复。完成后向用户汇报实际改动、实际测试、已发现/修复问题、仍未验证项，以及是否值得进入产品阶段；不自行提交、推送、部署或启用 AI，除非新任务另有相应授权。

## 9. 本轮设计核对结论

本轮只新增方案和交接入口，未实施上述拟建模块，未新增模型费用，未运行软件/数据库/硬件验收。已用当前仓库核对产品目标、治理接口依赖、现有恢复机制及旧原型位置。官方框架依据沿用 2026-10-07 的固定源码评估，本轮未重新做网络研究。

仍需执行阶段核实：现有回执对新答复的实际可复用程度、总尝试额度的持久预检适配、旧预算余额、当前模型兼容性、真实采集和课程许可材料。它们各自有明确阶段与失败处理，不用猜测填作已完成。
