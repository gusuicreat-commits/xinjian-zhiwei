## 实现及实际效果

| 规则 | 用户能观察到的变化 | 核心实现与验证 |
| --- | --- | --- |
| 身份与实验归属 | 正式学生使用个人账号，选择有资格的实验；设备密钥仅兼容明确测试演示。失效、借用和歧义不会转而读取其他学生数据 | `data_scope`、认证依赖、会话服务；个人账号/撤销选课/多角色/历史归属反例 |
| 会话开始和结束 | 同一设备不能被两个新会话同时占用；开始/结束保存原请求回执。会话固定实验包版本，结束实验不表示修好硬件 | 新0030迁移；PostgreSQL独立连接竞争只创建一个会话和回执 |
| 多问题 | 同一诊断的不同异常/不同部件分别持久化。主展示顺序不决定问题身份；多问题反馈必须指定目标 | `DiagnosisIssue`；规则顺序、分别关闭、同类不同部件指导测试 |
| 指导、时间和计数 | 只用当前故障相关的新来源证据增加一轮；同一原始日志重新产生规范化UUID不算新异常。实际观察跨度与等待帮助时长分开，未解决反馈不再增加异常证据轮次 | `diagnosis_episode`、`guidance`；历史/生命周期/并发回归 |
| 学生界面 | 可明确选中问题；指导、工单和反馈跟随所选目标。旧的单问题隐式反馈可用服务器原回执确认，不能借此接受不同的显式目标 | `DiagnosisPanel`、`feedbackRetry`；组件与回执测试 |
| 教师工单 | 处理完成与问题解决分开；明确报告问题解决走统一生命周期。学生报告解决会在已认领工单中留下公开事件及接收教师关联，不自动结案 | 工单服务、目标问题API、教师界面；原请求重复确认不增加版本和事件 |

## 已明确保留的边界和后续验收

1. 学生/教师报告解决只证明报告发生，不证明硬件恢复。自动验证恢复要求同范围、同规则版本、充分且新鲜的正常证据；缺少组件级恢复判据时不猜测局部硬件恢复。
2. 全局知识撤回不改写已发布包的固定副本。停止某个包的教学必须明确撤回该包；此时采集和历史记录保留。
3. AI金额防护为带币种、价目版本和UTC日期范围的估算预检，不宣称精确费用硬上限；未知费用保留待核对。
4. concepts/steps尚未在全部教学路径完整消费；本轮不把材料校验和存储当作全路径教学能力。没有新增“学生已经执行动作”的推断计数。
5. 真实板卡/器件参数、课程允许动作与验收阈值、教师真实根因材料和正式案例仍待负责人提供。第6阶段需要正常—受控单因素故障—修复恢复的独立实物对照及课堂试运行。
6. 本地完整门禁不等于云端CI实际执行或生产验收。云端CI、目标环境备份恢复演练、生产升级/回滚、真实课堂规模容量目标与压测没有执行；发布前按准则补验，不能跳过后宣称上线完成。

后续开发必须复用对应业务所有者，新增入口补入第20节对应表。变更模型、权限、状态、目标或证据来源时，同步更新契约、迁移、实现、反例测试与真实性记录；不能只修改断言接受新的行为。
