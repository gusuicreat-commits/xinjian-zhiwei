# 芯鉴知微文档索引

本索引区分持续规则、当前实现、验收方法、待评审方案和历史证据。阅读旧报告时先核对日期与版本；历史通过不能证明当前工作区、运行库、硬件或课堂已经验收。

## 从哪里开始

1. 开发前读[项目入口](../AGENTS.md)与[开发准则](development-guidelines.md)，特别是第19、20、21节。
2. 判断项目能做什么，读[当前实现状态](implementation-status.md)；判断哪些结论还不能确认，读[真实性看板](project-truth-status.md)。
3. 修改具体模块，再读下面对应契约及其代码、测试。验收方法与执行结果分开查。

## 冲突如何处理

**规范规定应该怎样做，代码与测试证明目前怎样做；两者不能互相冒充。**

- 用户当前明确要求及更高优先级约束优先；项目持续规则统一在开发准则维护。
- 当前代码、Schema、迁移和实际执行记录用于核对实现事实。若实现违背规则，应记录偏差并按授权修复，不能因代码已经这样写就降低规则。
- 当前设计文档须与实现同步；有意改变边界时先写清决策、兼容影响和反例，再同步规范、契约、实现与测试。
- 待评审方案不能覆盖已确认规则；原文示例、旧报告、交付快照不能证明当前部署、硬件参数或正式教师知识。

新增文档先判断属于哪一类，并从本索引链接。已在唯一位置维护的规则只引用；无独立内容的占位页可以删除，有独特事实的旧文档归档保留。
