# 受控查询复用与框架选型方案

日期：2026-10-07。状态：**仅设计，未实施、未运行模型评测、未启用产品能力。**

执行细化见[LangGraph受控查询详细方案](archive/langgraph-query-execution-plan-20261007.md)，转入新窗口可使用[交接文本](langgraph-query-handoff-20261007.md)。本方案保留设计时的选型边界；S0–S3评测已结束，原型已移除，现行产品采用确定性查询。

目标是验证动态查询和追问能否帮助学生更快取得有效证据。2026-10-07依据[开源复用与框架评估](agent-reuse-selection-20261007.md)修订：优先复用已有 LangGraph 和官方模板，先比较 A/B0；PydanticAI为第一备选，Pi为条件候选。先建设最小隔离对照，再决定产品接入；保留规则诊断、故障树、知识校验和教师确认职责。

持续约束以[开发准则](development-guidelines.md#model-core)及[AI质检](development-guidelines.md#ai-quality)为准。本文记录本次架构候选和验收安排，不新增第二份开发准则。

产品目标遵循[PRD](product-background-prd.md)的FR-04至FR-06：利用实际设备内部证据辅助诊断、说明与重新验证。首先核对可观测信号及区分能力；只有证据获取确需动态选择时才建设循环。效果对照分别记录信息增加的收益，以及同一证据下规则与规则加AI的差异；不以调用次数或框架接通作为成功条件。

## 2 架构决策

### 2.1 按需要激活实验组

| 组别 | 实现 | 比较目的 |
| --- | --- | --- |
| A | 冻结当前固定诊断流程和输出合同 | 记录当前可交付基线 |
| B0 | 复用 LangGraph 官方循环结构及本地任务合同，先沿用受管 JSON 动作选择 | 首先检查动态查询能力的收益，不新增模型运行栈 |
| B1 | 确有需求时，LangGraph 配合受管原生工具调用 | 与其他原生工具框架公平比较 |
| D | 有明确缺口时，用 PydanticAI适配同一任务和治理 | 优先核对Python备选是否减少实现与维护负担 |
| C | 仅在明确需要Pi运行/扩展能力时，启用隔离Node适配 | 检查收益是否足以抵消跨语言成本 |

A 与 B0 是能力增量比较，不能把差异全部归因于框架。B1/C/D 才是同能力框架比较：模型、业务提示、工具定义、信息权限、任务状态、预算及末端诊断合同保持一致；不可消除的序列化与协议差异单列。B0的JSON选择器不冒充原生function calling，不强求同时建设全部候选。下文B指当前激活的B0或B1；C/D未激活时相应实现和评测不执行。

首选已有LangGraph组件；官方模板的联网工具、直接模型调用及通用终止条件需改接项目合同，具体文件和许可见复用评估。若激活C，核心候选为 `pi-agent-core`。初期不引入完整 coding-agent 的默认资源发现、编程工具和自动摘要，不引入第二套权威会话库。`pi-durable` 的持久化能力作为参考，本轮不与业务库并行维护同一任务状态。完整编程助手辅助开发属于另一用途，不混入产品效果对照。

### 2.2 执行关系

```text
隔离评测输入或未来已认证请求
    → Python 任务服务：身份、范围、固定包、证据修订、许可目录
    → 计算 eligible_actions
    → B LangGraph / C Pi：提出下一动作
    → Python 共同执行器：重验后查询、登记问题或停止
    → 有界且带来源的结果交回循环
    → 现有候选推理、知识校验和受控交付
```

模型仅提出选择，执行许可和终态由代码决定。只有一个合格动作时直接按合同执行，不为制造“Agent 行为”增加模型调用。规则仍唯一决定 `error_type`，候选仍取故障树，查询完成不代表根因确认。

隔离实验使用各自独立的合成库或 schema；不读取真实学生记录，不自动给用户发问题，不驱动硬件。后续产品入口采用可关闭的旁路，失败保留当前合法确定性结果；撤权则拒绝访问，不能把权限拒绝包装成可查看的降级结果。

## 3 共用任务与工具合同

### 3.1 任务身份

服务端冻结 `run_id`、执行组、操作者、课程/任务/会话/设备归属、诊断身份、实验包版本及 hash、证据修订、合同版本、截止时间和预算身份。给模型的是最小化投影；真实学生身份与访问凭据不进入提示或工具参数。

模型请求只接受服务器已经发放的 `requirement_id`、`action_id`、`question_id` 和当前修订。任意实验、学生、路径、SQL、URL或数据库连接参数均不属于工具合同。校验器拒绝未声明字段，不静默忽略身份覆盖尝试。

### 3.2 首期能力

下列为拟新增的内部工具名，不是现有 API。

| 工具或动作 | 合格输入 | 结果与约束 |
| --- | --- | --- |
| `query_evidence` | 本任务有效 requirement_id | 读取当前授权快照中的相关记录，保留来源类型、修订和测试性质 |
| `query_package_requirement` | 本任务需求 ID | 读取已绑定版本中对应规范，不检索其他包补齐答案 |
| `query_approved_cases` | 本任务需求 ID | 复用资格与适用性匹配，权限、审核、版本和条件通过后才返回 |
| `propose_question` | eligible_actions 中的问题 ID | 服务端登记一道问题并生成许可文本，模型不自由编写操作建议 |
| `propose_finish` | 合同允许的终态及证据引用 | 服务端重算完成条件；错误提议没有终态写入或学生交付 |

查询资料“没有数据”和“没有权限”分别处理；权限拒绝不透露受限对象是否存在。工具内部执行后再次复核来源与范围，失效结果不回流模型。禁止通用 Shell、任意文件/网络访问、写数据库、发布知识或控制设备的工具。

### 3.3 材料和追问

- 材料状态沿用 `not_checked/present/checked_empty/conflicting/stale`。同来源同修订的别名不制造新证据；不同来源同文不能被文本去重误删。
- 先查相关存档；无有效材料或确需核对冲突时，才允许提问。过期材料重新询问必须绑定新的有效修订和原因。
- 问题目录登记适用实验、组件、阶段、器材/操作前提、目标材料类型、审核来源和有效版本；未审核项目只用于合成夹具。
- 同一需求同一修订已有 pending 或 answered 问题时不再发同题。答复可为“不知道/无法观察”，不会自动成为支持某候选的证据。
- 学生自述保存为报告类型；设备命令、配置读取和独立测量保留原语义。禁止从自由文本猜出“实测配置一致”或“根因已确认”。

正式目录缺失时，产品分支停止于资料不足或教师帮助；不得把原型的 `observe_led/confirm_config` 全局示例直接当课程批准事项。

## 4 Pi 适配与模型调用治理

本节仅在C组激活后执行。A/B0不需要Node、IPC或Pi专用沙箱。D组以Python依赖适配共同治理，延迟工具结果和用量限制不得替代业务授权与持久回执。

### 4.1 进程与通信

C 组使用受 Python 管理的 Node 子进程，通过专用标准输入/输出管道传 JSON 帧；不监听公共端口。进程运行在无 Provider/数据库凭据的隔离环境，文件系统只包含锁定运行依赖，网络出口禁用。操作系统隔离是执行条件，删环境变量不等于沙箱。

拟定帧字段：`protocol_version/run_id/request_id/expected_revision/kind/payload`。最大帧先按 256 KiB 作为试验候选；流式读取累计计数，超量即终止连接，不先完整读入。stderr 单独收集并脱敏；stdout 仅传协议。B 组也经过同一逻辑合同。精确上限进入单一评测 profile，并以实测容量核对，不在多处维护常量。

父进程是状态和执行许可的权威。Node 传来的身份、次数、费用和完成声明都重新校验。异组、异任务、过期修订和重复但内容不一致的帧拒绝；异常退出或超时只影响本次增强。

### 4.2 原生工具调用适配先行

Pi 的请求经自定义模型流接口送回 Python；Python 负责实际 Kimi 请求，Node 不直接调用 Provider。适配层需要显式验证：工具 JSON Schema、assistant/tool 消息、tool_call_id 配对、结束原因、usage、取消、错误和有界返回。

当前 `GovernedAIInvocation.complete_json` 不能被默认为完整 tool-calling 协议。C组实施第一步先形成一个最小适配探针，验证如何扩展共用客户端和治理入口，让 B1/C/D 共用同一受管的工具调用传输。若必须复制预算/重试逻辑或绕过治理才能连通，则 C 组记为受阻，先修订设计。

不能将普通 JSON 决策包装成虚构工具轨迹后宣称已经验证 Pi 原生工具调用。若后续确需 JSON 选择器模式，应另命名实验并说明与原生协议的差别。

### 4.3 唯一外发与重试位置

所有实际模型请求，包括选动作、终末推理、解释及任何未来摘要，统一进入治理入口；每次尝试发送前持久化请求身份与费用预留。Pi 端关闭独立重试、后台调用和自动摘要；发现隐含调用则不能进入效果评测。

等待锁/退避后及外发前重验授权和来源；模型返回后与最终读取时再验。失败、取消、超时已发生的用量照实记录；发送结果未知不自动重发或退款。外部在途请求不保证能被撤销，停止后禁止新的调用和失效结果交付。

缓存身份包含组别、合同/提示/工具 Schema、模型、材料指纹、包版本和证据修订，避免不同实验组互相命中而污染计费和效果。完成回放先重验权限，不能重新收费生成答案。

### 4.4 试验资源候选

以下是拟冻结的起始配置，尚未改变项目默认值；实施前用完整请求预检。有更严格的现有配置时取更严格者，禁止运行中自动放宽。

| 限制 | 候选值与范围 |
| --- | --- |
| 循环模型尝试 | 每任务最多 3 次，失败尝试也计入 |
| 全任务模型尝试 | 最多 5 次，包含后续现有推理/解释阶段；跨答复恢复不重置 |
| 业务查询 | 最多 4 次，首期顺序执行 |
| 提问 | 首期每任务最多 1 个新问题；答复后可以结束或降级 |
| 输入预算 | 每请求完整消息和工具 Schema 受现有配置限制；当前默认 10000，显式低限有效 |
| 工具结果 | 每次投影最多 8 KiB，完整证据单元入选，超量返回明确省略状态，不截断成伪完整证据 |
| 活跃执行期限 | 全任务候选 120 秒，跨恢复累计；各调用沿用更小的现有期限 |
| 人工等待 | 释放工作进程与锁；任务/会话到期或版本失效停止恢复，不无限占用执行槽 |
| 并发 | 初期真实模型评测并发 1；并发边界先用模拟 Provider 与隔离 PostgreSQL 测试 |

目前没有为本轮分配新增付费预算。将来运行前核对原有 ¥10 授权范围、已消费与在途预留，只能使用可确认的剩余额度；不能把旧上限当成新增 ¥10。估算不宣称账单硬上限，若无法可靠约束总费用，就先停留在离线评测并报告差额。

## 5 状态恢复和未来产品合同

### 5.1 状态含义

```text
created → running → awaiting_answer → running
                  → completed_satisfied / completed_unknown
                  → stopped_budget / stopped_no_progress / failed
                  → blocked_authorization / stale / cancelled / outcome_unknown
```

终态由服务器写入。`completed_satisfied` 只表示取证任务满足条件；`completed_unknown` 有明确证据缺口且无合格后续动作；预算、工具失败和无进展不伪装成正常完成。一次调用结果未知先等待核对，恢复不能自动再次发送该请求。

相同证据被不同工具返回、新 ID 指向相同来源，均不算进展。进展按需求状态变化、有效新观察或冲突澄清计算。不合格模型动作立即结束该模型回合，交确定性策略；不额外调用模型做纠错重试。

### 5.2 持久化与答复设计

隔离评测先复用现有checkpoint/恢复服务及测试存储，补充故障注入。只有现有设施不能满足明确需求时再增加适配，不新建通用调度器或会话树。产品阶段再追加正式迁移，候选对象如下；实施前核对是否能扩展已有对象，不预先认定必须新增三张表。

| 对象 | 必需内容及约束 |
| --- | --- |
| 查询任务 | 绑定诊断/操作者/固定范围、策略与合同、材料修订、状态、剩余额度、revision、截止时间；请求身份唯一 |
| 查询步骤 | run_id＋step_no 唯一、动作、参数指纹、来源引用、结果码、调用操作引用；追加记录，不靠 transcript 当事实库 |
| 问题及答复 | 任务/需求/材料修订/问题目录版本、pending/answered/cancelled、答复请求 ID 与内容指纹、报告来源、提交人和时间 |

答复持久化、问题状态转换和恢复事件写入同一事务。唯一键及 revision 条件更新保证一次消费；同答复请求同内容返回原回执，同 ID 异内容返回冲突。网络超时后客户端查询原回执，不创建新任务。

恢复先复用当前工作流行锁和操作回执。若后续确需跨进程异步工作者接管，才引入短事务抢占与有期限租约，附单调递增的执行代次作为 fencing token；每次执行和写入验证当前代次，过期工作进程不能继续。租约接管也不能绕过 `dispatching/outcome_unknown` 的禁止重发规则。不在等待学生或 Provider 时持有业务行锁。

新答复沿既有来源路径产生新材料或新诊断修订；旧诊断快照不变。恢复重新核对身份、会话、来源、包、答复关联及全部剩余额度。问题版本与答复不兼容时拒绝，不把旧答案套在新问题上。

### 5.3 产品界面和接口的后续范围

候选接口职责为创建/查询任务、提交答复、取消与查询回执，路径和精确 Schema 在产品阶段同步 API 文档。采用现有登录权限、CSRF及请求身份机制；新增状态码映射覆盖 401/403/409/资源不足，不能一直显示“等待 AI”。

前端只展示服务端生成的查询进度、许可问题、来源与终态；模型 token 不直接作为指导流式展示。刷新、切页、换账号与迟到响应按 task_id/revision 校验。学生随时可保留当前规则结果或请求教师帮助，Agent 不自行改变故障计数和介入状态。

任务、步骤及答复的索引按本人任务列表、待恢复任务和回执查找设计，列表分页；敏感内容保留与遗忘沿既有生命周期策略。期限未确定时保留待决，不猜保留天数，不把取消操作当作删除证据。

## 6 规则归属与必测入口

以下是本方案的影响映射。产品实施时更新开发准则的唯一规则表和对应模块契约，本轮不改动现行产品边界。

| 现有规则 | 共同执行位置 | 新入口与验收反例 |
| --- | --- | --- |
| AUTH / SESSION | 后端身份与 data_scope 服务 | 启动、工具前后、等待后、答复、恢复、回放、读取；等待期间撤权，零禁止调用与交付 |
| EVIDENCE / CTX | 来源注册、证据投影、上下文合同 | 查询结果、再外发、终末结果；同源别名、独立同文、错包、超量整单元、来源撤回 |
| AI | governance、清洗、客户端与持久回执 | Pi 桥接/B 适配/重试/取消；并发预算、隐含调用、锁超时、结果未知、重复计费 |
| SEM / KNOWLEDGE | 输出合同、知识验证、current_advice | 新结果、旧缓存、历史、二阶段、页面；unknown 不补原因、自由断言不泄入产品 |
| RECOVERY | 查询任务服务与既有操作回执 | 重复答复、乱序消息、双进程恢复、丢响应、崩溃、旧进程复活；每个副作用有唯一身份 |
| QUERY 任务合同 | 从原型提炼的唯一资格与状态函数 | 先查后问、跨实验问题、已答重复问、伪进展、提前 finish；各增强组同合同 |

必须继续检查：CoT请求配置与审计、原 LangGraph 图及反馈恢复、完整上下文单元与两阶段来源清单、案例适用、三类记忆与停用、资料包参考、输出合同和预算。P4、真实配置和课程许可未完成项单列，不能被新 Agent 掩盖。

## 7 评测设计与选择判据

### 7.1 分层验证

1. **无模型合同检查**：冻结原型反例和正常对照；用脚本工具与模型替身检查全部状态和禁止副作用。关键守卫用隔离破坏确认反例确实能失败。
2. **真实存储与进程检查**：隔离 PostgreSQL 锁/竞争/回滚和恢复去重；仅C激活时检查Node协议超量/崩溃/取消。计数以实际调用与落库为准。
3. **Kimi兼容小样本**：最少量合成材料核对工具调用请求、结束、错误及用量；不先跑大批能力评测。失败先修适配，不调整教学预期。
4. **已激活组效果对照**：先A/B0；出现明确能力缺口才增加B1与D或C。冻结后运行保留集，盲化组别供人工语义检查。教师未审查时保持 not_run/null。
5. **产品集成验收**：只有选型获采纳后实施 API、迁移、前端及默认关闭开关，再跑相关回归和一次必要完整门禁。真实课堂另行验收。

### 7.2 样本与公平性

起始样本计划为 12 个开发样本与 24 个独立保留样本；保留集按以下 8 类各 3 个不同情境建立。样本规模用于发现问题，不宣称统计充分或代表真实课堂分布。

| 类别 | 主要检验 |
| --- | --- |
| 已有充分材料 | 不重复查询/追问，原有合法指导可用 |
| 缺材料但工具可查 | 查询正确来源，不把可查问题转嫁学生 |
| 需学生补充 | 问题符合课程，答复后正确恢复 |
| 已回答或明确无法观察 | 不重复追问，不假设肯定答案 |
| 冲突、过时、不可区分根因 | 保留状态差别、unknown 与报告语义 |
| 身份、来源和版本变化 | 及时停止，缓存/恢复/交付同样受约束 |
| 失败与资源边界 | 超时、超量、预算、崩溃、未知结果不伪装完成 |
| 注入与越界诱导 | 材料中命令、伪造 ID、任意 URL/路径不变成许可 |

输入、独立预期和固定模拟答复分别存储，答案与评测标签不进入模型。开发/保留集按情境、会话、设备和模板家族隔离；对保留集修改提示后，该批转为开发样本，补新保留集。历史失败原样保留作回归，不冒充新保留集。

所有激活的增强组使用完全相同的许可目录、任务函数和工具内容；规则基线也不得独享“正确下一步”等辅助标志。A 保持原能力；补充做一组统一材料回放，让已激活各组终末诊断拿到相同合法材料，用来区分“取到了新资料”和“末端推理改变”的收益。

拟每情境每组重复 3 次，运行顺序轮换，记录 Provider、模型、参数、价格快照、错误与调用身份。按剩余额度分完整配对批次执行，额度不足保留 incomplete，不只挑能通过的案例、不自动加钱。模拟学生答复只证明软件路径，不证明真人理解或操作效果。

### 7.3 判据和报告

Rubric 沿用“一条一事、符合/不符合”的规范，未审阅为 null；不设综合分抵消权限或语义不符合。复用现有 semantic_rubrics 中适用项，新增仅限工具过程和追问要求，并建立实例映射。

- 必须符合：范围和来源正确、无禁止副作用、重复操作不重发、资源上限有效、未知不伪装确定、问题合格且不重复、终态与真实步骤一致。
- 描述性数据：需求是否得到有效满足、有效查询及提问次数、到有效下一步的耗时、首响应时间、失败/降级原因、实际尝试和费用。报告分母、缺失值与逐案例配对差异，不用汇总值掩盖失败。
- 人工语义：证据是否支持结论、追问是否有必要且在课程范围内、遗漏是否影响指导。由独立材料和教师判定，模型自评不作为通过依据。
- 选择：先排除未满足必需条件的方案。通过者比较配对收益、成本和维护负担；差异不足或不稳定则继续采用现有方案。增强组效果相近且 B 维护成本低时优先 B；D或C有可复现额外收益才建议相应产品接入，决策注明具体案例和代价。

真实 API、软件断言、语义审阅、硬件、课堂分别出结果，不将参考测试数量叠加成“全面通过”。报告格式沿[测试报告约定](test-reporting.md)，未来输出到 `output/audits/pi-controlled-query-<实际日期>/`，附源码指纹、锁文件、工具与合同版本、输入指纹、实际配置、逐步脱敏轨迹、费用账和未执行项。

## 8 实施顺序与退出条件

| 阶段 | 可审查交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| S0 复用与基线 | 准确源码身份、上游组件/许可清单、共用任务合同、最小B0设计 | 优先复用现有接口，历史反例和合法对照可复现；C/D适配不作为B0前置条件 |
| S1 离线原型 | 受版本控制的B0原型、共享工具、复用存储、失败时序测试 | 无禁止副作用，旧流程回归符合，独立预期不泄漏；其他组按缺口激活 |
| S2 合成真实模型 | 兼容记录、配对轨迹、成本与不符合项 | 额度可确认，真实协议正常；失败先定位修复后重验 |
| S3 选型结论 | 已激活组逐例比较、教师语义状态、组件采用或不采纳理由 | 有足够证据判断收益；不足则继续保持原方案，不能仅为比较而扩建框架 |
| S4 产品候选 | 追加迁移、API/前端、恢复、开关、规则表与全链路验收 | 明确采纳产品接入；完成课程许可与真实材料前提 |

每阶段先复现目标反例、定位共同原因，再改实现；通过相称检查后停止无目的扩测。身份泄露、越权、重复外发、失效来源交付立即停止该候选的后续效果试验并保留取证。

隔离阶段撤回只需停止候选进程并禁用评测入口，保留脱敏证据。产品阶段预设开关关闭新增任务与新调用、取消在途增强交付、保留回执和未知费用待核对；旧记录只读投影，不删证据、不自动降级数据库，不恢复旧权限缺陷。故障期间学生仍能使用原有规则诊断与教师帮助。
