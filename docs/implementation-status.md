## 知识、规则和 AI 边界

- 当前 YAML 阈值和故障树属于示例规则、占位规则或待确认参数，未由硬件说明书、课程
  资料、行业标准或真实故障样本验证。
- PostgreSQL 中只有明确测试标记的合成知识和测试向量；正式查询默认排除它们。
- 对话 AI 的 Phase 9.5 默认路由已选择 DeepSeek 兼容配置，但
  `AI_ENABLED=false`，无 API Key、无数据外发审批、无收费调用。
- Embedding Provider、模型和维度仍未确认。未配置时系统使用确定性规则、故障树和
  可用的全文检索，不伪造向量。
- AI 不得更改确定性故障类型或证据；Provider 关闭、超时、预算不足、知识不足或输出
  非法时，系统返回确定性结果。

## 仍需人工提供或确认

1. 硬件 BOM、型号/版本、原理图、接线、GPIO、供电、安全限制和正式固件。
2. 传感器字段、单位、量程、精度、采样/心跳/重试策略和正式错误码。
3. 实验目标、步骤、正常范围、完成条件、故障真值、确认根因和最终修复动作。
4. 可授权知识文件、来源 URI、版本、适用硬件、许可证，以及整理、技术审核、正式批准
   三类人员的结论。
5. 正式用户、课程、班级、角色、任务和设备绑定清单。
6. AI 密钥、费用与频率上限、数据外发/保留审批；Embedding 方案。
7. 生产域名、HTTPS、网络拓扑、密钥管理、监控告警、备份责任、保留期限和验收指标。

这些输入未完成前，readiness 的总体状态应保持 `blocked`，不得对外宣称具备真实硬件
故障诊断能力。
