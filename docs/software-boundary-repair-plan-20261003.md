## 文档预算与历史兼容决策

原始导入文本仍受当时的文档字符上限（工作区已移除）限制。自动分块会复制重叠正文，资源计量需保留这一合法行为：新增仅服务器可写的`KnowledgeChunk.overlap_credit_chars`，记录导入算法确实复制的字符额度；编辑不会新增额度，缩短时额度最多等于实际长度，拆分只能分配原有额度，合并只能合计原有额度。文档计量为所有块的实际长度减已有额度之和；新增内容始终消耗预算，重复拆分/合并不能凭空增加额度。API不接受客户端写此列。

迁移0039为历史块填0，不推测旧locator是否仍对应原文；不改历史内容、审核或测试标记。历史或降低配置后已超限的草稿，允许严格减少总量的修整，拒绝增加或等量超限内容替换；元数据维护和只读不触发新内容写。提交审核/批准时必须满足现行总量预算。迁移用数据库约束保证额度非负且不超过块长度；存在非零额度时拒绝有损降级。上线需要单独执行迁移；本轮仅在隔离测试库验证。

## 实施顺序与自核

1. 保留扫描失败证据，在常规测试中新增独立规则断言，先验证旧实现确实失败。
2. 实施来源标记、现有正式文档写保护与审计；再实施锁内总量/重叠额度及HTTP/Nginx边界。
3. 针对已知公告解算兼容依赖，保留原锁差异及官方查询依据；网络测试使用隔离服务，不向业务或公网目标发送攻击数据。
4. 定向回归、真实PG竞争/迁移、Linux和代理补验完成后，对最终候选跑一次完整门禁。失败按原因修复，避免用放宽断言掩盖问题。
5. 核对差异、规则表和状态文档；保存报告/源码身份、清理本轮资源。

自核结论：已覆盖创建/去重/文件转文本/编辑/拆分/合并/删除/审核/审计，以及并发锁后的最终检查；合法重叠不误算为新内容。拒绝路径在业务赋值/审计之前；source/document与授权保持既有锁序；不在解析或外部调用期间持有授权锁。旧数据无法确认的性质不自动改写，旧超限数据提供减少式修整路径。上述预期先成为测试，再实施。

回退：代码与依赖锁作为一致候选回退；保留新增列及已记账额度，不通过删除额度回退数据。业务库迁移、部署、真实模型、硬件和课堂不在本轮自动执行范围。
